## 本次修改
### 目標
讓 `mkdocs serve -f mkdocs.preview.yml --dirty` 也能使用右鍵跳回 Markdown 原文檔功能。

### 問題根因
- 原本的 `_PAGE_INDEX` 只在 `on_page_markdown` 建立。
- 實測在目前專案的 `serve` 流程中，lookup endpoint 雖然存在，但某些 preview 頁面沒有對應索引，導致按右鍵選單後開檔失敗。

### 採用做法
- 新增 `on_files`，在檔案集合建立完成後先讀取所有 Markdown 文檔並建立索引。
- 使用 `mkdocs.plugins.event_priority(-100)`，讓預索引在其他 `on_files` 操作之後執行，避免過早讀到未穩定的檔案集合。
- 保留原有 `on_page_markdown`，讓真正渲染的頁面內容可以覆蓋預索引，兼顧穩定與準確度。
- `.gitignore` 內原本以檔名匹配的協作檔忽略規則，改成 `/README_PEICD100.md`、`/專案規格書.md`、`/log.md` 這種根目錄限定寫法，讓 `codex/` 下的新正式協作檔能被版本控制。
- 新增 `tools/run_logged.py`，讓後續人工驗證命令的輸出統一寫到 `codex/tmp/`，避免根目錄堆積 `.out.log` / `.err.log`。
- `.gitignore` 以 `/codex/tmp/*` 搭配 `!/codex/tmp/.gitkeep` 保留目錄本身，避免直接忽略整個父目錄後無法重新納入佔位檔。

### 設計理由
- 官方文件指出 `on_files` 會在 `docs_dir` 檔案集合完成後觸發，適合新增、移除或調整檔案集合，也明確建議 MkDocs 1.6 起可在 `on_files` 使用 `File.content_string` / `content_bytes`。
- 這種做法不依賴單一頁面一定先經過 render event，對 `serve` / `dirty` 類工作流更穩。
- `.gitignore` 的未加路徑檔名規則會連子目錄同名檔一起匹配；改成根目錄限定可以保留舊檔忽略意圖，同時避免誤傷 `codex/` 內的正式替代檔。
- Python 官方文件建議一般子程序使用 `subprocess.run()`，而且用參數序列比 shell 字串更穩；這裡直接把 `stdout/stderr` 分流寫檔，降低後續驗證輸出散落根目錄的機率。
- Git 官方文件指出忽略規則若直接排除父目錄，之後不能再重新納入子檔案；因此 `codex/tmp/` 採「忽略內容、保留 `.gitkeep`」而不是整個目錄直接忽略。

## 2026-04-12 標題 inline code 版面修正
### 目標
- 修正 Markdown 標題內使用 backticks 時，MkDocs 頁面把 inline code 拉成異常大方塊、甚至拆行錯位的問題。

### 問題根因
- `docs/theme/assets/pymdownx-extras/自定義.css` 先前把 `h2~h6` 設成 `display: flex`，但 `align-items` 寫成了無效值 `top`。
- 在 flex 容器中，標題裡的純文字、`code`、`headerlink` 會各自成為 flex item；`align-items: top` 失效後實際回退到 stretch，導致 `code` 被拉高。
- 當標題同時含有多個 code span 時，flex item 的縮放與換行又會把 code 內容拆得很難看。

### 採用做法
- 保留既有 `h2~h6` 的 flex 佈局，避免連動破壞自訂錨點圖示順序。
- 將 `align-items` 改成 `flex-start`，並補上 `flex-wrap: wrap`，讓標題可在項目間換行而不是硬把 code 拉伸。
- 另外新增 heading 內 `code` 的專屬樣式：縮小字級、減少 padding、桌機預設 `nowrap`，手機寬度再退回可換行。

### 設計理由
- CommonMark 規範明確指出 heading 內容會以 inline content 解析，所以 heading 內放 code span 本來就是合法寫法；問題在本站自訂版面，而不是 Markdown 語法本身。
- Python-Markdown TOC 文件也直接示範了 heading 內使用 code span 的情境，代表這種寫法在 MkDocs 生態內是常見需求。
- 社群經驗顯示 heading 雖可含 inline code，但 rich heading 很依賴站點 CSS；因此這次優先修 CSS 根因，而不是只改單一 Markdown 標題。

## 2026-04-12 頁面內目錄序號修正
### 目標
- 修正 `VHDL.md` 頁面內手寫目錄出現 `a.`、`b.` 之類錯誤標號的問題。

### 問題根因
- `## 目錄` 下方目前是手寫無序清單。
- 其中頂層條目原本寫成 `- 1. ...`、`- 2. ...` 這種格式。
- Python-Markdown 在 block parsing 階段會把這些內容解讀成「無序清單項目內再包一層有序清單」。
- 瀏覽器對這種巢狀 `<ol>` 預設常用 `lower-alpha`，所以畫面上才會出現 `a.`。

### 採用做法
- 將 `- 1. ...` 改成 `- 1&#46; ...`，其他頂層條目同理。
- 保留現有手寫目錄結構與文案，不額外改成自動 TOC 或重做連結格式，避免影響使用者既有編排。

### 設計理由
- CommonMark / Python-Markdown 的 block parsing 會先處理清單結構，再處理一般 inline escape，因此單純把點改成 `\.` 在這個情境下不夠穩。
- 改用 `&#46;` 後，原始 Markdown 不再符合 ordered list marker 的語法，實測可穩定輸出成單純文字 `1.`。
- 相比直接重寫整段目錄成 HTML 或改成另一套標記，這個修改最小，也最不容易破壞既有內容。

## 2026-04-12 標題 inline code 上下置中
### 目標
- 讓標題中使用 backticks 的 inline code 和周圍文字上下置中。

### 問題根因
- 目前 `h2~h6` 已改為 flex 容器，heading 內的 `code` 會成為 flex item。
- 既有 `align-items: flex-start` 是為了避免 heading 內容被 stretch，但它也讓 code item 靠上。
- 使用者這次要的是明確的上下置中，而不是只靠視覺微調。

### 採用做法
- 保留既有 heading flex 佈局與 heading code 尺寸設定。
- 在 heading code 規則改用 `align-self: center`，讓 code item 相對於同一條 flex line 在 cross axis 上置中。
- 移除先前的 `top` 微位移做法，避免結構性對齊與視覺 nudging 疊加。

### 設計理由
- MDN 說明 `align-self` 可覆寫單一 flex item 的 cross-axis 對齊，這正好符合「只把 heading 裡的 code 置中、其他項目維持原本對齊」的需求。
- 比起整個 heading 容器改成 `align-items: center`，只調 code item 的 `align-self` 影響面更小，也不容易牽動錨點圖示。
- 社群常見做法也是先用 flex 的原生對齊屬性解決垂直置中，再考慮 optical nudge；這次採更語意化也更穩的前者。

## 2026-04-18 單頁 preview 快捷命令
### 目標
- 讓使用者能直接在終端輸入一個命令加 Markdown 路徑，自動切換 `mkdocs.preview.yml` 的預覽目標，並立刻用 `mkdocs_desk` 啟動 preview serve。

### 問題根因
- 目前 `mkdocs.preview.yml` 需要手動改 `nav` 與 `exclude_docs`，每次切換預覽頁都要手改 YAML。
- 使用者常用的是 PowerShell 終端，但 Conda 啟用流程較穩的是 `cmd`/batch 內透過 `activate.bat` + `conda activate` 串接。
- 使用者輸入的路徑可能是專案根目錄相對路徑（`docs\...`），也可能是 `docs_dir` 相對路徑（`md\...`），若不統一正規化，`mkdocs.preview.yml` 會寫錯。

### 採用做法
- 新增根目錄 `preview.bat`，作為終端命令入口。
- `preview.bat` 會先偵測 Conda base，再直接呼叫 `<conda_root>\condabin\conda.bat activate mkdocs_desk`。
- 新增 `tools/update_preview_config.py`，負責驗證目標 Markdown 是否位於 `docs/` 內、將輸入路徑正規化為 `docs_dir` 相對路徑，並更新 `mkdocs.preview.yml`。
- `mkdocs.preview.yml` 新增 `# preview-target:start` / `# preview-target:end` managed 區塊，讓工具只改這一段，避免誤傷其他 preview 專用設定。
- `preview.bat` 完成設定更新後，再執行 `python -m mkdocs serve -f mkdocs.preview.yml --dirty`。

### 設計理由
- MkDocs 官方文件說明 `nav` 參照的是 `docs_dir` 內文件，而 `exclude_docs` 使用類似 `.gitignore` 的相對模式；因此工具應統一輸出成 `docs_dir` 相對路徑，避免 `docs/...` 直接寫進 config 造成錯誤。
- MkDocs 1.6 release notes 指出 `exclude_docs` 下的 Markdown 在 `mkdocs serve` 仍可作為預覽頁使用；目前的單頁 preview 策略可以延續，不需要改整套 preview 架構。
- Stack Overflow 上針對 Windows/Conda 的經驗普遍指出，批次流程需要透過 `call` 進入 Conda 的 batch 入口才不會中斷；本機實測中，直接呼叫 `condabin\conda.bat activate mkdocs_desk` 比 `activate.bat` 再轉一次更穩，所以正式入口採前者。
- 本機實測中，環境啟用後直接呼叫 `mkdocs serve` 的 wrapper 沒有穩定拉起服務，但 `python -m mkdocs serve` 正常；因此正式入口改用模組方式啟動，以降低 PATH / shim 差異。
- 用 managed block 更新 YAML，比整份重新 dump 更穩，因為可以保留 `INHERIT`、`plugins` 與未來可能新增的 preview 額外設定。

## 2026-04-23 右下角 Back to bottom 按鈕
### 目標
- 在不改動 Material 內建 `navigation.top` 的前提下，新增一顆右下角固定的 `Back to bottom` 按鈕，方便使用者快速跳到頁尾。

### 問題根因
- 現有站點只有 Material 內建的 `Back to top`，而且它是置中顯示、只在特定捲動方向下出現。
- 使用者這次要的是另一顆獨立存在的頁尾快捷按鈕，不能去覆蓋或改壞現有的 `Back to top` 行為。
- 專案同時啟用了 `navigation.instant`，若只靠單次 `DOMContentLoaded` 綁定，自訂按鈕在切頁後很容易失效或重複掛事件。

### 採用做法
- 在 `docs/theme/main.html` 覆寫 `footer` block，保留 `{{ super() }}` 後再 include `docs/theme/partials/scroll-bottom.html`，避免直接覆蓋 Material 的 `base.html`。
- 新增 `docs/theme/partials/scroll-bottom.html`，固定輸出 `button[data-peicd-scroll-bottom]`，按鈕文案維持英文 `Back to bottom`，並使用 Material `arrow-down` 圖示。
- 在 `docs/theme/partials/libs.html` 載入 `docs/theme/assets/pymdownx-extras/scroll-bottom.js`，不去碰 `mkdocs.yml`。
- `scroll-bottom.js` 以 `DOMContentLoaded` + `window.document$.subscribe(...)` 初始化，並用模組層級旗標確保 `scroll` / `resize` 事件只綁一次。
- 顯示條件採：
  - 頁面不可捲動時隱藏
  - 已接近頁尾（`scrollTop >= maxScroll - 24`）時隱藏
  - 其餘情況顯示
- 點擊按鈕時用 `window.scrollTo({ top: maxScroll, behavior })`；若偵測到 `prefers-reduced-motion: reduce`，則退回 `auto`。
- `docs/theme/assets/pymdownx-extras/自定義.css` 新增 `.peicd-scroll-bottom` 樣式，外觀以 Material `.md-top` 為基底，但改成固定在右下角；手機版縮小 padding，並隱藏文字只保留 icon。

### 設計理由
- Material 官方文件指出 `navigation.top` 的按鈕是內建功能，且會置中顯示在頁首下方；因此這次不去覆寫它，而是新增獨立按鈕，能降低和上游模板耦合。
- Material 官方 customization 文件明確建議自訂 JS 在有 instant loading 時要掛在 `document$` observable；因此這次沿用專案現有 `folder-path-bar.js` 等檔案的初始化模式。
- MDN 文件說明 `window.scrollTo()` 可直接指定 `{ top, behavior }`，而 `prefers-reduced-motion` 可用來在使用者要求減少動畫時關掉平滑滾動；這樣可同時兼顧體驗與可近用性。
- 社群對 MkDocs Material 的 customization 經驗普遍偏向「用額外 CSS / JS 與 partial 做最小覆蓋」，而不是直接改安裝套件內模板；這次也採同方向。
