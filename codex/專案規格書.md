# 專案規格書

## 專案定位
- 專案名稱：`university notes`
- 型態：MkDocs Material 筆記網站
- 主要內容：課程筆記、Verilog 快速整理、自訂互動功能
- 執行環境：conda `mkdocs`

## 主要結構
- `docs/`：Markdown 內容、圖片、Logo
- `docs/theme/`：覆蓋 Material 的主題模板與前端資產
- `tools/`：MkDocs hooks 與輔助腳本
- `mkdocs.yml`：主站設定
- `mkdocs.preview.yml`：單頁 preview 設定
- `vbs_bat/`：Windows 雙擊啟動包裝

## 關鍵技術
- MkDocs
- MkDocs Material
- MkDocs hooks
- 自訂前端 JS / CSS

## Source Jump 功能設計
- 前端：`docs/theme/assets/pymdownx-extras/source-jump.js`
  - 限定 `mkdocs serve` 本機預覽時啟用
  - 右鍵選單提供「開啟原文檔案」與「複製」
- 後端：`tools/source_jump_hook.py`
  - `on_serve` 提供 `__peicd/source-jump` lookup endpoint
  - `on_files` 預先掃描 Markdown，建立 `_PAGE_INDEX`
  - `on_page_markdown` 在頁面實際渲染時，用更接近最終輸出的 Markdown 重新覆寫索引

## 本次修改
### 目標
讓 `mkdocs serve -f mkdocs.preview.yml --dirty` 也能使用右鍵跳回 Markdown 原文檔功能。

### 問題根因
- 原本的 `_PAGE_INDEX` 只在 `on_page_markdown` 建立。
- 實測在目前專案的 `serve` 流程中，lookup endpoint 雖然存在，但某些 preview 頁面沒有對應索引，導致按右鍵選單後開檔失敗。

### 採用做法
- 新增 `on_files`，在檔案集合建立完成後先讀取所有 Markdown 文檔並建立索引。
- 使用 `mkdocs.plugins.event_priority(-100)`，讓預索引在其他 `on_files` 操作之後執行，避免過早讀到未穩定的檔案集合。
- 保留原有 `on_page_markdown`，讓真正渲染的頁面內容可以覆蓋預索引，兼顧穩定與準確度。
- `.gitignore` 內原本以檔名匹配的協作檔忽略規則，改成 `/README_PEICD100.md`、`/專案規格書.md`、`/log.md` 這種根目錄限定寫法，讓 `codex/` 下的新正式協作檔能被版本控制。

### 設計理由
- 官方文件指出 `on_files` 會在 `docs_dir` 檔案集合完成後觸發，適合新增、移除或調整檔案集合，也明確建議 MkDocs 1.6 起可在 `on_files` 使用 `File.content_string` / `content_bytes`。
- 這種做法不依賴單一頁面一定先經過 render event，對 `serve` / `dirty` 類工作流更穩。
- `.gitignore` 的未加路徑檔名規則會連子目錄同名檔一起匹配；改成根目錄限定可以保留舊檔忽略意圖，同時避免誤傷 `codex/` 內的正式替代檔。
