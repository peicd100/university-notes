# 協作重要事項

- 目前工作樹已有使用者未提交的既有變更；除非任務直接相關，避免碰觸 `mkdocs.yml` 與現有 Markdown 內容。
- `source-jump` 功能的穩定性不要再只依賴 `on_page_markdown`；目前正式做法是 `on_files` 先建索引，`on_page_markdown` 再覆寫精修。
- `mkdocs.preview.yml` 現況由 `preview.bat` 管理，檔案內目前預設值是 `md/114-2/科技_計算機結構/ch 2.md`；之後若要切換 preview 頁面，優先用命令更新，不要再手改 `nav` / `exclude_docs`。
- `mkdocs.preview.yml` 的單頁 preview 目標現在由 `preview.bat` + `tools/update_preview_config.py` 維護，正式寫入區段是 `# preview-target:start` 到 `# preview-target:end`；需要加其他 preview 設定時，放在區塊外。
- 本專案的右鍵跳回原文檔功能只在本機 `mkdocs serve` 預覽時啟用，靜態站點不會啟用。
- `.gitignore` 內協作檔忽略規則要用根目錄限定寫法（例如 `/README_PEICD100.md`），避免 `codex/` 內同名檔被一起忽略。
- Windows 下的單頁 preview 快捷命令目前採 batch 入口，不直接依賴 PowerShell 啟用 Conda；本機正式做法是直接呼叫 `<conda_root>\condabin\conda.bat activate mkdocs_desk`。
- Windows 下的單頁 preview 快捷命令啟用環境後，正式用 `python -m mkdocs serve -f mkdocs.preview.yml --dirty`，不要再依賴 `mkdocs` wrapper。
- 後續人工驗證若要保留 `stdout/stderr`，統一使用 `tools/run_logged.py`，輸出寫到 `codex/tmp/`；不要再在根目錄直接留下 `.out.log` / `.err.log`。
- `docs/theme/assets/pymdownx-extras/自定義.css` 內的 `h2~h6` 目前仍使用 flex 佈局承接自訂錨點圖示，但 `align-items` 不能用無效的 `top`；要用 `flex-start`，否則標題內的 `code` / 其他 inline 節點會被拉成異常的 flex item。
- 手寫 Markdown 目錄若放在無序清單內，`- 1. 標題` 會被 Python-Markdown 解析成「`<ul>` 裡包 `<ol>`」，瀏覽器預設第二層有序清單會顯示成 `a.`。目前較穩的避法是把點寫成 `&#46;`，例如 `- 1&#46; 標題`。
- 標題內的 inline code 目前採 `align-self: center` 做 cross-axis 置中；不要再和先前的 `top` 微移做法混用。
