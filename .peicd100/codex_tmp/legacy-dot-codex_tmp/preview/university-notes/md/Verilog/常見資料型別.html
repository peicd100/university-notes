    常見資料型別

    一張先看懂的大圖

    Verilog 常見資料型別可先分成兩大類：`net(網路型別)` 與 `variable(變數型別)`。`wire` 屬於 net；`reg`、`integer`、`time`、`real` 等屬於 variable。這個分類很重要，因為它直接決定「它像一條線，還是像一個會被程序改寫的變數」。([VerilogPro](https://www.verilogpro.com/verilog-reg-verilog-wire-systemverilog-logic/?utm_source=chatgpt.com))

    先講結論：你平常寫 RTL 最常用的是誰？

    在 Verilog RTL(日常可綜合電路) 裡，最常用的通常就是：

    • wire：拿來表示連線(connection)，常搭配 assign
    • reg：拿來表示在 always / initial 裡被賦值的變數
    • integer：常拿來當for 迴圈索引(loop index)、計數用暫時變數，不是拿來取代一般多位元訊號的第一選擇 (VerilogPro)

    你可以先用一句話背：

    `assign` 左邊通常用 `wire`；`always` 左邊通常用 `reg`；`integer` 通常拿來做整數計數或迴圈索引。 ([Electrical Engineering Stack Exchange](https://electronics.stackexchange.com/questions/671829/deciding-data-types-of-input-and-output-ports-in-verilog?utm_source=chatgpt.com))

    1. wire 是什麼？

    `wire` 是 **net(網路型別)**，比較像硬體裡的「線」。它本身**不主動存值**，而是呈現目前驅動它(driver)的結果。通常由 `assign`、模組輸出、或其他元件來驅動。([Stack Overflow](https://stackoverflow.com/questions/33459048/what-is-the-difference-between-reg-and-wire-in-a-verilog-module?utm_source=chatgpt.com))

    生活化理解

    你可以把 wire 想成「延長線」：

    • 插頭有電，它就有電
    • 沒人驅動時，常看到的是高阻抗 z
    • 它自己不是拿來「記住」資料的盒子 (logicmadness.com)

    最常見寫法

    wire y;

assign y = a & b;

這表示 `y` 持續等於 `a & b`。([Stack Overflow](https://stackoverflow.com/questions/33459048/what-is-the-difference-between-reg-and-wire-in-a-verilog-module?utm_source=chatgpt.com))

    2. reg 是什麼？

    reg 是 variable(變數型別)。它的重點不是「它一定是暫存器(register)」，而是：

    它可以在 `always` / `initial` 這種 procedural block(程序區塊) 裡被賦值。([VerilogPro](https://www.verilogpro.com/verilog-reg-verilog-wire-systemverilog-logic/?utm_source=chatgpt.com))

這是初學者最常誤解的地方： **`reg` 不等於硬體暫存器(register)**。它最後會被綜合成什麼，要看你怎麼寫。若寫在 `always @(*)` 可能是組合邏輯；若寫在 `always @(posedge clk)` 才常是 D flip-flop(D 型正反器)。([VerilogPro](https://www.verilogpro.com/verilog-reg-verilog-wire-systemverilog-logic/?utm_source=chatgpt.com))

    生活化理解

    把 reg 想成白板上的數字：

    • 你在 always 裡寫了一次，它會保持那個值
    • 直到下次你再改它
    • 但「白板」不一定代表最後硬體一定是暫存器，還是要看更新條件 (VerilogPro)

    最常見寫法

    reg y;

always @(*) begin

    y = a & b;

end

這裡 `y` 不是因為「要做暫存器」才用 `reg`，而是因為它在 `always` 裡被賦值，所以語法上要是 `reg`。([VerilogPro](https://www.verilogpro.com/verilog-reg-verilog-wire-systemverilog-logic/?utm_source=chatgpt.com))

    3. integer 是什麼？

    `integer` 也是 **variable(變數型別)**。在常見 Verilog 工具與現代標準實作下，通常把它視為 **32-bit signed(32 位元有號整數)**；社群與工具文件也普遍這樣使用。([Stack Overflow](https://stackoverflow.com/questions/40009716/size-of-integers-in-verilog?utm_source=chatgpt.com))

    它跟 reg [31:0] 差在哪？

    兩者都能放數字，但語意不同：

    • reg [31:0]：你明確指定「這是一個 32-bit 向量」
    • integer：你是在說「這是一個整數」，通常預設帶有 signed(有號) 整數語意，且寬度不是用位元切片來表達 (Stack Overflow)

    最常見用途

    integer 最常見於：

    • for 迴圈索引
    • 測試平台(testbench) 計數
    • 少量整數運算或暫存控制值 (Nandland)

    例如：

    integer i;

always @(*) begin

    for (i = 0; i < 8; i = i + 1)

        y[i] = a[i] & b[i];

end

這種用法很常見，而且 `for` 在可綜合條件下是能綜合的，重點是展開次數必須能在編譯時決定。([Electrical Engineering Stack Exchange](https://electronics.stackexchange.com/questions/350078/question-about-synthesizable-for-loop-and-generate?utm_source=chatgpt.com))

    為什麼需要同時有 wire、reg、integer？

    因為 Verilog 不是一般軟體語言，它是 Hardware Description Language(硬體描述語言)。 硬體裡真的有兩種很不同的東西：

    1. 連線(connection)：像電路中的線，誰驅動它，它就反映誰
    2. 程序中被賦值的變數(variable assigned procedurally)：像你在 always 裡一步一步算出來的結果 (VerilogPro)

    所以 Verilog 才把型別拆成：

    • wire 這種「像線」的東西
    • reg / integer 這種「像程序變數」的東西 (VerilogPro)

    用 C++ 類比

    若硬比喻：

    • wire 比較像「函式輸出端一直即時連到某個表達式」
    • reg 比較像「區塊中的變數」
    • integer 比較像「你拿來跑迴圈的 int i」 (Electrical Engineering Stack Exchange)

    什麼時候用 wire？

    用在這些情況

    • assign 左邊
    • 接子模組(submodule) 的輸出
    • 單純做訊號連接
    • 不需要在 always / initial 中直接賦值 (Stack Overflow)

    典型例子

    wire sum;

assign sum = a ^ b ^ cin;

    你可以這樣記

    看到「這條訊號只是被接出來、被連過去、被持續驅動」，優先想到 `wire`。([Stack Overflow](https://stackoverflow.com/questions/33459048/what-is-the-difference-between-reg-and-wire-in-a-verilog-module?utm_source=chatgpt.com))

    什麼時候用 reg？

    用在這些情況

    • 你要在 always 裡對它賦值
    • 組合邏輯 always @(*)
    • 時序邏輯 always @(posedge clk) (VerilogPro)

    典型例子 1：組合邏輯

    reg y;

always @(*) begin

    y = (sel) ? a : b;

end

    典型例子 2：時序邏輯

    reg q;

always @(posedge clk) begin

    q <= d;

end

    你可以這樣記

    只要「左值」出現在 `always` 裡，先優先想到 `reg`。這是 HDLBits 初期非常好用的判斷法。([Electrical Engineering Stack Exchange](https://electronics.stackexchange.com/questions/671829/deciding-data-types-of-input-and-output-ports-in-verilog?utm_source=chatgpt.com))

    什麼時候用 integer？

    用在這些情況

    • for 迴圈索引
    • testbench 中的整數計數
    • 少量控制計數，不特別需要明確位元寬度時 (Nandland)

    典型例子

    integer i;

always @(*) begin

    for (i = 0; i < 4; i = i + 1)

        out[i] = in[i];

end

    但不要濫用

    在 RTL 裡，如果你要表示明確寬度的硬體訊號，通常還是更建議用：

    reg [7:0] count;

wire [15:0] data;

而不是什麼都寫成 `integer`。因為 `reg [N:0]` 的位元寬度更清楚，也更符合你真的想合成出來的硬體。([Stack Overflow](https://stackoverflow.com/questions/61312493/what-is-the-difference-between-the-integer-and-reg-variable-types-in-verilog?utm_source=chatgpt.com))

    input / output 預設是什麼？

    在 Verilog 裡：

    • input 預設是 wire
    • output 預設也是 wire
    • inout 也預設是 wire (Stack Overflow)

    也就是說：

    input a;

output y;

    等同於：

    input wire a;

output wire y;

    那什麼時候寫 output reg？

    當 `output` 這個埠要在 `always` 裡被賦值時，就常寫成 `output reg`。([Stack Overflow](https://stackoverflow.com/questions/5360508/using-wire-or-reg-with-input-or-output?utm_source=chatgpt.com))

    例如：

    module top_module(

    input  a,

    input  b,

    output reg y

);

always @(*) begin

    y = a & b;

end

endmodule

這裡 `y` 寫成 `reg`，是因為它在 `always` 裡被指定，不是因為它一定會被綜合成「實體暫存器」。([Stack Overflow](https://stackoverflow.com/questions/5360508/using-wire-or-reg-with-input-or-output?utm_source=chatgpt.com))

    一份很好背的選擇規則

    規則 1

    `assign` 左邊 → 通常 `wire`。([Electrical Engineering Stack Exchange](https://electronics.stackexchange.com/questions/671829/deciding-data-types-of-input-and-output-ports-in-verilog?utm_source=chatgpt.com))

    規則 2

    `always` 左邊 → 通常 `reg`。([Electrical Engineering Stack Exchange](https://electronics.stackexchange.com/questions/671829/deciding-data-types-of-input-and-output-ports-in-verilog?utm_source=chatgpt.com))

    規則 3

    `for (i=...)` 的 `i` → 常用 `integer`。([Nandland](https://nandland.com/for-loop-2/?utm_source=chatgpt.com))

    規則 4

    要描述固定寬度的硬體資料路徑(data path)，優先用 `wire [N:0]` 或 `reg [N:0]`，不要把 `integer` 當萬用替代品。([Stack Overflow](https://stackoverflow.com/questions/61312493/what-is-the-difference-between-the-integer-and-reg-variable-types-in-verilog?utm_source=chatgpt.com))

    常見誤解，我直接幫你踩煞車

    誤解 1：reg 就是 register(暫存器)

    ❌ 不對。 `reg` 是 Verilog 的 variable 型別；它可描述組合邏輯，也可描述時序邏輯。([VerilogPro](https://www.verilogpro.com/verilog-reg-verilog-wire-systemverilog-logic/?utm_source=chatgpt.com))

    誤解 2：wire 不能接複雜邏輯

    ❌ 不對。 只要是連續指定 `assign` 或模組輸出驅動，它很常拿來接各種組合邏輯結果。([Stack Overflow](https://stackoverflow.com/questions/33459048/what-is-the-difference-between-reg-and-wire-in-a-verilog-module?utm_source=chatgpt.com))

    誤解 3：integer 不能綜合

    ❌ 不完全對。 它常用於可綜合的 `for` 迴圈索引；只是 RTL 資料路徑若想清楚控制位寬，通常不建議用它當一般訊號。([Electrical Engineering Stack Exchange](https://electronics.stackexchange.com/questions/350078/question-about-synthesizable-for-loop-and-generate?utm_source=chatgpt.com))

    除了上面三個，還有哪些型別？

    若以傳統 Verilog 來看，除了 wire、reg、integer，常見還有：

    1. 其他 net 型別

    • tri
    • wand
    • wor
    • triand
    • trior
    • tri0
    • tri1
    • supply0
    • supply1
    • trireg (ChipVerify)
    這些多半用在較特殊的網路解析、多驅動、上拉/下拉、儲存性網路建模。**RTL 初學和 HDLBits 前期幾乎用不到**，你先知道名字就夠了。([ChipVerify](https://www.chipverify.com/verilog/verilog-net-types?utm_source=chatgpt.com))

    2. 其他 variable 型別

    • time
    • real
    • realtime (ElectroSofts)

    這些大多偏模擬(simulation)與 testbench 用途：

    • time：記模擬時間
    • real / realtime：浮點數模擬，不是一般綜合 RTL 的主角 (ElectroSofts)

    3. 事件型別

    • event (八位元學院)
    這更偏模擬控制流程，不是你做基本 RTL 時天天會碰到的東西。([八位元學院](https://www.theoctetinstitute.com/content/verilog/verilog-data-types/?utm_source=chatgpt.com))

    對 HDLBits 最實用的版本

    如果你的目標是先把 HDLBits 做穩，我建議你先用這套簡化心法：

    • 模組輸入 input：先當 wire
    • 模組輸出 output：預設 wire
    • 如果 output 要在 always 裡改：寫 output reg
    • 模組內中介連線：通常 wire
    • 在 always 裡被賦值的中介變數：通常 reg
    • 迴圈索引 i：通常 integer (Stack Overflow)
    這套規則不是整個 Verilog 世界的全部，但對入門 RTL 很夠用，而且不容易踩大雷。([VerilogPro](https://www.verilogpro.com/verilog-reg-verilog-wire-systemverilog-logic/?utm_source=chatgpt.com))

    最後幫你濃縮成一份超短版

    wire

    像「線」，不自己存值；通常給 `assign`、模組連接用。([Stack Overflow](https://stackoverflow.com/questions/33459048/what-is-the-difference-between-reg-and-wire-in-a-verilog-module?utm_source=chatgpt.com))

    reg

    像「程序變數」；通常在 `always` / `initial` 裡賦值。不是看到 `reg` 就等於硬體暫存器。([VerilogPro](https://www.verilogpro.com/verilog-reg-verilog-wire-systemverilog-logic/?utm_source=chatgpt.com))

    integer

    整數型別，常見為 32-bit signed；最常拿來做 `for` 迴圈索引與整數計數。([Stack Overflow](https://stackoverflow.com/questions/40009716/size-of-integers-in-verilog?utm_source=chatgpt.com))

    預設埠型別

    `input/output/inout` 預設都是 `wire`。([Stack Overflow](https://stackoverflow.com/questions/71625202/what-is-the-default-data-type-of-verilog-input-port-variables?utm_source=chatgpt.com))

    一個小提醒：實務上更好的寫法

    雖然你現在是學 Verilog，但很多現代專案會改用 SystemVerilog 的 `logic` 來降低 `reg` / `wire` 名稱造成的誤解。不過在 HDLBits 與純 Verilog 題目裡，我們還是先把 `wire`、`reg`、`integer` 觀念練扎實最重要。([VerilogPro](https://www.verilogpro.com/verilog-reg-verilog-wire-systemverilog-logic/?utm_source=chatgpt.com))
