# 運算子

## 1) Bitwise operators（位元運算子）

### 常見運算子
- `~` : bitwise NOT
- `&` : bitwise AND
- `|` : bitwise OR
- `^` : bitwise XOR
- `~^` / `^~` : bitwise XNOR

### 核心觀念
bitwise 會對 **每一個 bit 各自運算**。

```verilog
a = 4'b0101;
b = 4'b0011;
y = a | b;      // y = 4'b0111
```

等價於逐位計算：

```text
0 | 0 = 0
1 | 0 = 1
0 | 1 = 1
1 | 1 = 1
```

### 記法
- 輸入是 `n-bit`
- 輸出通常也是 `n-bit`

可以把它想成 C++ 對整個整數做 `& | ^ ~`，只是硬體上本質是「每個 bit 平行運算」。

---

## 2) Logical operators（邏輯運算子）

### 常見運算子
- `!` : logical NOT
- `&&` : logical AND
- `||` : logical OR

### 核心觀念
logical **不是逐 bit 算**，而是把整個 operand 當成布林值：

- 非 0 → true
- 0 → false

最後輸出 **永遠是 1 bit**。

```verilog
a = 3'b101;   // true
b = 3'b110;   // true

x = a || b;   // x = 1'b1
```

### 記法
- 輸入可以是很多 bit
- 但輸出只會是 `1 bit`

這很像 C++：
- `a | b` 是位元 OR
- `a || b` 是布林 OR

---

## 3) Bitwise vs Logical 對照表

### bitwise OR

```verilog
a | b
```

- 逐 bit OR
- 輸出寬度通常跟運算式位寬一致

```verilog
a = 3'b101;
b = 3'b110;
a | b = 3'b111;
```

### logical OR

```verilog
a || b
```

- 把 `a`、`b` 整體當真假
- 輸出永遠是 `1 bit`

```verilog
a = 3'b101;   // true
b = 3'b110;   // true
a || b = 1'b1;
```

## 4) 不同位寬做 bitwise 時，怎麼決定結果？

### 先記一句
對 `& | ^ ^~ ~^ + - * / %` 這類 binary operators，
**expression 的位寬先看 operands 與 context（例如賦值左邊）**。

最常見好記版：
- 單看 `A & B` 這個 expression，本身位寬通常是 `max(width(A), width(B))`
- 若它出現在 assignment 右邊，整個 expression evaluation 還會受左值位寬影響
- 最後 assign 到左邊時，可能再被 **補位** 或 **截斷**

### 例子

```verilog
wire [2:0] A = 3'b011;
wire [4:0] B = 5'b10011;
wire [3:0] C;

assign C = A & B;
```

### 可以這樣理解
先把較小的 operand 擴成較大的位寬來做運算：

```text
A -> 5'b00011
B -> 5'b10011
--------------
A & B = 5'b00011
```

然後 assign 到 `C[3:0]`：

```text
C = 4'b0011
```

### 重點
不是「先對齊到 C 再做 `&`」；
而是「先決定 expression 的位寬並完成運算，再依左邊需要補位或截斷」。

## 5) Reduction operators（縮減運算子）

這一類是很多 HDLBits 題目很常用的偷懶寫法。

### 常見寫法
- `&in` : 把所有 bit AND 起來
- `|in` : 把所有 bit OR 起來
- `^in` : 把所有 bit XOR 起來
- `~&in` : reduction NAND
- `~|in` : reduction NOR
- `~^in` / `^~in` : reduction XNOR

### 例子

```verilog
wire [3:0] in;

assign out_and = &in;   // in[3] & in[2] & in[1] & in[0]
assign out_or  = |in;   // in[3] | in[2] | in[1] | in[0]
assign out_xor = ^in;   // in[3] ^ in[2] ^ in[1] ^ in[0]
```

### 重點
- reduction operator 的輸出一定是 `1 bit`
- `&in` 跟 `&(in[3:0])` 在這裡等價
- 這不是 logical operator

### 注意
不能寫：

```verilog
&&in   // 錯
```

因為 `&&` 是 **binary operator（二元運算子）**，一定要有左右兩邊。

## 6) Arithmetic（四則運算）

### 常見運算子
- `+`
- `-`
- `*`
- `/`
- `%`

### 你要分三件事看

#### (a) value（值）
數學上答案是多少。

```text
1 + 1 = 2
5 - 8 = -3
5 / 2 = 2   // integer division 不是 2.5
```

#### (b) bit width（位寬）
我有幾個 bit 可以裝結果。

#### (c) signed / unsigned（有號 / 無號）
同一串 bit，要把它看成可正可負，還是只當正數。

---

## 7) Arithmetic 的位寬規則

### 基本版
對 `+ - * / % & | ^ ^~ ~^`
expression 位寬通常先看：

```text
max(L(i), L(j))
```

也就是左右 operand 誰比較寬，就先用誰。

### 但 assignment context 很重要
如果這個 expression 放在 assignment 右邊，
**整個 expression evaluation 也會被左邊位寬影響**。

```verilog
wire [3:0] a, b;
reg  [15:0] sumA;
reg  [16:0] sumB;

sumA = a + b;   // 以 16 bits 評估
sumB = a + b;   // 以 17 bits 評估
```

### 記憶法
右邊不是永遠自己算自己的。
當它被 assign 給左邊時，左邊像是「要多大的盒子」，會影響右邊計算時開多大的空間。

### 常見坑
```verilog
reg [15:0] a, b, ans;
ans = (a + b) >> 1;
```

如果你原本想保留 carry，這樣可能不夠，因為 `(a+b)` 可能先用 16-bit 算完後就把 carry 丟掉。

更安全常見寫法：

```verilog
reg [16:0] tmp;
reg [15:0] ans;

always @(*) begin
    tmp = a + b;
    ans = tmp >> 1;
end
```

或直接：

```verilog
reg [15:0] ans;
assign ans = {1'b0, a} + {1'b0, b};
```

如果只想拿低 16 位，則可再明確 slice。

## 8) signed / unsigned 規則

### 規則摘要
- 如果任何 operand 是 `real`，結果就是 `real`
- 否則，只要任何 operand 是 `unsigned`，結果就偏向 `unsigned`
- 只有當所有 operands 都是 `signed`，結果才是 `signed`

### unsigned（無號數）
只能表示非負整數。

### signed（有號數）
可表示正負，Verilog 一般用 two's complement（二補數）。

### real（實數）
`real` 是實數型別。

當 real 轉 integer 時：
- 會四捨五入到最近整數
- 如果剛好 `.5`，會 **遠離 0**

例子：

```text
35.5 -> 36
1.5  -> 2
-1.5 -> -2
```

## 9) 比較運算子（Comparison operators）

### Relational operators
- `<`
- `>`
- `<=`
- `>=`

### Equality operators
- `==`
- `!=`
- `===`
- `!==`

### 核心觀念
比較運算最後輸出都是 **1 bit**。

```verilog
(a < b)
(a == b)
```

都只會得到：
- `1'b1`
- `1'b0`
- 某些情況 `1'bx`

---

## 10) `==` / `!=` 與 `===` / `!==` 差別

### `==` / `!=`（logical equality / inequality）
- 會做一般比較
- 如果任一 operand 裡有 `x` 或 `z`，而且導致結果無法確定
- 結果會是 **`1'bx`**

```verilog
4'b10x1 == 4'b1001   // 結果可能是 x
```

### `===` / `!==`（case equality / case inequality）
- 會把 `x`、`z` 也當成可比較的值
- 結果一定是 `1'b0` 或 `1'b1`

```verilog
4'b10x1 === 4'b10x1   // 1
4'b10z1 === 4'b1001   // 0
```

### 記法
- `==`：像「一般數值比較」
- `===`：像「bit pattern 完全一模一樣才算相等」

## 11) 最常考觀念整理

### Q1. `|` 跟 `||` 差在哪？
- `|`：bitwise，逐 bit，輸出通常是多 bit
- `||`：logical，把整體看真假，輸出永遠 1 bit

### Q2. `&in` 是什麼？
是 reduction AND，把所有 bit AND 起來，輸出 1 bit。

### Q3. `a+b` 一定會自動多 1 bit 保留 carry 嗎？
不一定。Verilog 的 expression width 要看 operands 與 context，不能直接假設會自動幫你留 carry。

### Q4. `==` 遇到 `x/z` 會怎樣？
可能得到 `1'bx`。

### Q5. `===` 遇到 `x/z` 呢？
照樣比，結果一定是 `1'b0` 或 `1'b1`。

---

## 12) HDLBits 角度的速記版

### 一眼判斷
- 看到 `& | ^ ~` → 先想 **bitwise**
- 看到 `&& || !` → 先想 **logical**
- 看到前綴 `&in |in ^in` → 先想 **reduction**
- 看到 `== !=` → 小心 `x/z`
- 看到 `=== !==` → 連 `x/z` 都一起比

### 背法
- bitwise：**每一位都算**
- logical：**整包當真假**
- reduction：**整包壓成 1 bit**
- comparison：**結果永遠 1 bit**

## 13) 寫題時的實戰建議

### 建議 1
如果你在意 carry / overflow，不要只憑感覺寫：

```verilog
assign sum = a + b;
```

最好明確把位寬拉大：

```verilog
assign sum = {1'b0, a} + {1'b0, b};
```

### 建議 2
如果你只是想判斷「這整個 bus 是否非零」，用 logical 很直觀：

```verilog
assign valid = (bus != 0);
// 或
assign valid = |bus;
```

### 建議 3
如果題目要你「全部為 1」、「至少一個為 1」、「奇偶檢查」，先想 reduction：

```verilog
assign all_ones = &in;
assign any_one  = |in;
assign parity   = ^in;
```
