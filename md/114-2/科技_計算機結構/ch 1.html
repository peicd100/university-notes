    這張投影片在回答一個核心問題：

    人類寫的程式，最後怎麼變成 CPU 看得懂的東西？

    它在講的是一條由上而下的轉換路徑：

    高階語言(High-level language) → 組合語言(Assembly language) → 機器語言(Machine code) → 硬體執行

    你可以把它想成：

    • 高階語言：像人話，比較好寫
    • 組合語言(Assembly language)：比較接近 CPU 指令的「助記符號」
    • 機器語言(Machine code)：CPU 真正直接讀的 0 和 1

    這頁的重點是：硬體最後只吃 bit(位元)，所以不管前面寫得多漂亮，最後都要變成二進位。(維基百科)

    逐句解釋投影片內容

    1.「計算機硬體的字母僅有兩個」

    投影片寫的是：

    • 二進制位元(binary digit) 或位元(bit)

    意思是： 電腦硬體底層通常只用兩種狀態表示資訊，例如：

    • 高電壓 / 低電壓
    • 有電 / 沒電
    • 1 / 0

    所以才會說電腦的「字母」只有兩個：0 和 1。

    你可以把它想成開關：

    • 開 = 1
    • 關 = 0

    很多個 bit 排在一起，就能表示數字、字母、圖片、指令。

    2.「計算機受我們的命令——稱之為指令(instruction)所控制」

    這句的意思是：

    CPU 不會「理解我們的想法」，它只會執行一條一條很明確的指令(instruction)。

    例如很抽象地說，可能有這類指令：

    • 加法 add
    • 搬移資料 move / load / store
    • 跳躍 jump
    • 比較 compare

    也就是說，電腦做事不是靠「理解語意」，而是靠一串格式固定的指令。 這和我們平常講自然語言非常不一樣。

    3.「組譯器(assembler)將一道以符號表示的指令翻譯成二進位形式」

    這句是整張圖最重要的地方，但也最容易混淆。

    先分清楚兩個名詞：

    • Assembly language(組合語言)：像 add A, B 這種人比較看得懂的符號式寫法
    • Assembler(組譯器)：負責把組合語言翻成機器碼的工具程式

    也就是說：

    • add A, B 不是 assembler
    • 它是 assembly language
    • 真正做翻譯的是 assembler

    這點要特別修正一下，因為很多初學者會把兩者混在一起。 根據資料，assembly language 是與特定 CPU 架構高度對應的低階語言，而 assembler 是把這些 mnemonic(助記符) 轉成 machine code(機器碼) 的程式。(維基百科)

    add A,B -> 1000110010100000 這一行怎麼看

    這行是在表達：

    「人看的符號指令」可以被翻成「CPU 看得懂的 bit 串」

    但這裡要注意一件事：

    這不是普世固定寫法

    add A, B 對不同 ISA(Instruction Set Architecture，指令集架構) 可能會有不同編碼。

    也就是說：

    • x86 的編碼方式可能不同
    • ARM 的編碼方式可能不同
    • MIPS 的編碼方式也可能不同

    所以這個 1000110010100000 比較像是示意圖，用來表達「組合語言最後會被編成二進位」這件事， 不是所有 CPU 都一定這樣編。(維基百科)

    我們可以怎麼理解這整個流程

    用一個生活化比喻：

    你對餐廳下單：

    • 你說：「我要一份牛肉麵，不要香菜。」 這像高階語言(High-level language)
    • 店員把它整理成內部簡寫單號 這像組合語言(Assembly language)
    • 廚房機器只認特定代碼，例如餐點編號、加料旗標 這像機器語言(Machine code)

    所以中間需要一個「翻譯角色」，把比較好懂的表示法，轉成最底層可執行的格式。

    下一步我們可以接著講：為什麼 CPU 不能直接執行高階語言，而一定要先變成組合語言／機器語言？

    組譯器(assembler)和編譯器一樣嗎

    不一樣，但兩者都是翻譯程式。

    最簡單的分法是：

    • Assembler(組譯器)：把 Assembly language(組合語言) 轉成 Machine code(機器碼)
    • Compiler(編譯器)：把 High-level language(高階語言)，例如 C、C++、Rust，轉成較低階的表示，通常最後也會變成機器碼或目標碼(object code) (維基百科)

    你可以把它想成什麼？

    像翻譯文件：

    • 組合語言本來就已經很接近 CPU 的語言
    • 高階語言離硬體比較遠，比較像人寫給人的語言

    所以：

    • Assembler 做的是「比較直接的對照翻譯」
    • Compiler 做的是「比較複雜的轉換與分析」

    為什麼不一樣？

    因為 Assembly language(組合語言) 和機器指令通常有很強的對應關係，常常接近 1 對 1。 例如一個 mnemonic(助記符) 指令，會對應到某個 opcode(操作碼) 編碼。Assembler 還會幫你做像是符號位址解析、常數計算、macro(巨集) 展開這些工作。(維基百科)

    但 Compiler(編譯器) 面對的是像 C、C++ 這種高階語言。它不只是「逐字翻譯」，還要處理：

    • 語法分析(syntax analysis)
    • 型別檢查(type checking)
    • 最佳化(optimization)
    • 產生目標碼(code generation)

    所以 compiler 通常比 assembler 複雜很多。(維基百科)

    一個具體例子

    假設你寫：

    a = b + c;

    這是高階語言。 Compiler(編譯器) 可能先把它轉成某種中間表示，再決定要不要放進 register(暫存器)、怎麼排指令、要不要做最佳化，最後才產生接近：

    MOV R1, b

    ADD R1, c

    MOV a, R1

    然後這些 assembly code(組合語言程式碼)，再交給 Assembler(組譯器) 轉成真正的二進位機器碼。這也就是為什麼在很多工具鏈(toolchain) 中，兩者會連在一起用。(維基百科)

    • Compiler 處理高階語言

    所以考試如果問「組譯器和編譯器一樣嗎」，

    compiler 負責把高階語言往低階轉，assembler 負責把組合語言變成機器碼。 (維基百科)

    下一步最適合接著講的是：那 Interpreter(直譯器) 又和 Compiler(編譯器) 差在哪裡？

    把 assembly language(組合語言) 轉成 machine code(機器碼)是不是就是 decode

    不是。把 assembly language(組合語言) 轉成 machine code(機器碼)，通常叫做 assemble / assembly(組譯)； decode(解碼) 是 CPU 在執行機器碼時，分析這串 bit 代表什麼操作。(維基百科)

    先直接分清楚

    1. Assembler(組譯器)在做什麼

    Assembler 的工作是：

    • 輸入：ADD R1, R2
    • 輸出：對應的 machine code(機器碼) bit pattern

    也就是把人可讀的組合語言助記符(mnemonic)，轉成CPU 可儲存與執行的二進位編碼。這件事叫 assembling(組譯)，不是 decode。(維基百科)

    2. Decode(解碼)在做什麼

    Decode 是 CPU 內部 instruction cycle(指令週期) 的一部分。 CPU 先從記憶體 fetch(取指)，拿到一串 machine code 之後，在 decode 階段把它拆解成：

    • 這是哪一種指令
    • opcode(操作碼) 是什麼
    • operand(運算元) 在哪裡
    • 要控制哪些電路、暫存器、ALU

    也就是說，decode 是把已經是 machine code 的 bit，轉成控制訊號(control signals) 讓硬體真的去做事。(維基百科)

    你可以把兩者想成兩個完全不同的時機

    組譯 assemble

    發生在程式被建立的時候

    • 你寫 assembly code
    • assembler 幫你翻成 machine code
    • 產生可執行檔或目標檔的一部分
    解碼 decode

    發生在CPU 正在執行程式的時候

    • CPU 從記憶體抓到 machine code
    • CPU 內部的 decoder(解碼器) 看懂這條指令要做什麼
    • 然後發控制訊號給硬體

    所以兩者差很多：

    • assemble：把文字指令翻成位元
    • decode：把位元指令解讀成硬體動作

    一個生活化例子

    像你去餐廳：

    Assembler 像什麼？

    你寫菜單代號：

    • 「牛肉麵加蛋」

    內部系統把它轉成：

    • A17-X2

    這像 assembler：把較好懂的表示法，轉成機器內部用的代碼。

    Decode 像什麼？

    廚房拿到 A17-X2 之後：

    • 看懂 A17 是牛肉麵
    • X2 是加蛋
    • 然後通知不同工作站開始動作

    這像 decode：不是在翻譯成另一種檔案格式，而是在理解代碼、啟動執行流程。

    這張圖是在回答一個很核心的問題：

    人類寫的程式，為什麼最後能變成 CPU 看得懂的東西？

    1. High-level programming language(高階程式語言) 例如 C 這是人比較容易寫、比較容易看懂的語言。

    2. Assembly language(組合語言) 這是比較接近硬體、接近 CPU 指令的文字表示法。 人還能勉強讀，但已經很低階了。

    右上角是一段 C 程式，大意是交換兩個陣列元素：

    int temp;

temp = v[k];

v[k] = v[k+1];

v[k+1] = temp;

    }

    這是 高階語言 C，重點是「容易讓人表達邏輯」。

    Compiler(編譯器)

    Compiler(編譯器)會把 C 這種高階語言，轉成 Assembly language(組合語言)。 圖中間那段像：

    • sll
    • add
    • lw
    • sw
    • jr

    • 從記憶體讀資料

    CPU 到底怎麼工作？

    1. CPU 稱為處理器 Processor

    2. 計算機的主動部分，依計算機程式的指示動作

    這句很重要。

    CPU 不會自己亂做事，它是按照program(程式) 裡的 instruction(指令) 做事。 例如程式寫：

    • 加 1
    • 顯示結果

    datapath(數據通道) 是什麼？

    datapath 是 CPU 裡面真正處理資料流動與運算的部分，常包含：

    • ALU(Arithmetic Logic Unit，算術邏輯單元)：加減乘除、AND、OR、比較

    • buses / multiplexers：在各元件之間搬資料、選路徑

    簡單說：

    datapath = 資料在哪裡、怎麼流、怎麼算

    也就是投影片下面那句：

    control(控制單元) 是什麼？

    control unit 會根據目前指令，產生 control signals(控制訊號)，去告訴其他部分：

    • 這次 ALU 要做加法還是減法
    • 哪個暫存器要讀
    • 哪個暫存器要寫
    • 要不要讀記憶體
    • 要不要寫記憶體
    • 程式計數器 PC 要不要跳轉

    所以投影片下面那句：

    控制處理器內根據程式中各指令來下命令給數據通道、記憶體、輸入輸出裝置的部分

    這句基本上就是 control unit 的核心意思。 (GeeksforGeeks)

    • control unit = 下命令的人
    • datapath = 真正做資料處理的一整套硬體

    而 datapath 裡面常見包含：

    • ALU(算術邏輯單元)
    • register file(暫存器組)
    • bus(匯流排)
    • MUX 多工器
    • adder(加法器)
    • 有時也會把和資料流直接相關的記憶體存取路徑一起畫進 datapath

    為什麼不只 ALU 和暫存器？

    因為 CPU 執行一條指令時，不是只有「算」而已，還要先把資料送到對的位置。

    例如這條：

    R1 = R2 + R3

    實際上不只是 ALU 做加法，還包含：

    1. 從 R2 讀資料
    2. 從 R3 讀資料
    3. 經過某些資料路徑送進 ALU
    4. ALU 做加法
    5. 把結果送回 R1

    所以除了 ALU 和 register，中間那條資料怎麼流的路徑 也很重要，這整套才是 datapath。

    你可以這樣說，會比較標準

    口語版

    ALU 和暫存器都屬於 datapath，但 datapath 不只包含它們，還包含讓資料流動和選擇路徑的其他硬體。

    考試版

    Datapath(數據通道) 是 CPU 中負責資料傳送、暫存與算術邏輯運算的硬體集合，通常包含 ALU、registers、buses、multiplexers 等；control unit(控制單元) 則負責產生控制訊號，協調 datapath 的運作。(GeeksforGeeks)

    電腦執行程式時，程式和資料暫時放在哪裡？ 答案就是：主記憶體(main memory)，而現在一般電腦的主記憶體主要就是 DRAM。投影片內容可在課程投影片中對照。

    先看投影片每一句在說什麼

    1. 記憶體(memory)是程式執行時存放它們的地方

    這句話可以先理解成：

    • 程式本來可能放在 SSD、硬碟
    • 但 CPU 不會直接很有效率地從 SSD 慢慢執行程式
    • 真正要跑程式時，會先把需要的程式碼和資料載入 主記憶體(main memory)

    生活化比喻：

    • SSD / 硬碟像倉庫
    • DRAM 像你的書桌
    • CPU 像正在做題目的人

    你不會每做一步都跑去倉庫拿東西，而是先把需要的資料攤在桌上。

    2. 記憶體由 DRAM 晶片構成

    這裡的「記憶體」在這堂課通常是在指：

    • 主記憶體(main memory)
    • 我們平常插在主機板上的 RAM 模組

    而這些模組內部，主要是由 DRAM chips 組成。這點和現代電腦的標準做法一致；DRAM 仍是主記憶體的主流技術。(TechTarget)

    3. DRAM = Dynamic Random Access Memory

    這個名詞可以拆成三段來記：

    Dynamic(動態)

    意思是：資料不是穩穩放著就好，要定期補電(refresh，重新整理)。

    因為 DRAM 的每個 bit 通常是靠 電容(capacitor) 儲存電荷，電荷會慢慢漏掉，所以必須週期性 refresh，不然資料會消失。這也是它叫做 dynamic 的原因。(TechTarget)

    Random Access(隨機存取)

    意思是： 理論上可以直接指定任一個位址(address) 去讀寫，而不用像磁帶那樣從頭一路捲到目標位置。

    也就是說：

    • 要讀第 10 格，可以直接讀
    • 要讀第 100000 格，也可以直接讀
    • 不需要先經過前面所有資料

    這就是「隨機存取」的核心概念。TechTarget 對 RAM 的描述也是處理器可以隨機存取任意儲存位置，而不是必須按順序取資料。(TechTarget)

    Memory(記憶體)

    就是拿來暫時存放正在使用的程式和資料。

    4. 我們使用多個 DRAMs 一起存放程式指令與數據

    這句是在說：

    一條記憶體模組不是只有一個超大儲存格，而是由很多 DRAM cell / DRAM chips 一起組成。

    原因很簡單：

    • 一個 cell 只能存很少資料
    • CPU 一次常常要讀很多 bit
    • 所以需要很多顆一起配合，組成完整的記憶體模組

    你可以把它想成：

    不是只有一個大倉庫格子，而是很多小抽屜組成整個櫃子。

    5. 為什麼叫 random access？

    投影片最後一句在強調：

    相對於磁帶這種 sequential access(循序存取) 裝置，DRAM 的存取不像磁帶那樣要依序走過前面內容。

    磁帶的感覺像：

    • 你要第 50 分鐘的片段
    • 得先從前面慢慢轉到那裡

    DRAM 的感覺像：

    • 你知道抽屜編號，就直接拉開那格

    所以在概念上，不同位置的存取時間大致相近。這正是 random access memory 的意思。(維基百科)

    但這張投影片有一個地方要更精確一點

    投影片寫：

    不論要存取的記憶體位置為何，記憶體的存取基本上需要的時間相同

    這句作為入門理解是可以的，但如果我們講精確一點，應該補一句：

    這是概念上的簡化說法，不是工程上絕對完全一樣。

    原因是現代 DRAM 實際運作時還有：

    • row(列) / column(行) 選取
    • row buffer
    • bank
    • burst transfer
    • memory controller(記憶體控制器)

    所以不同情況下，延遲(latency) 其實可能不同。 例如：

    • 如果要讀的資料剛好在已開啟的 row，上手比較快
    • 如果要先關閉別的 row 再開新 row，就比較慢

    所以更精確的說法應該是：

    RAM 的存取不像磁帶那樣必須依序掃過前面資料；它支援以位址直接選取資料位置。入門上可視為任意位置都能直接存取，但實際延遲仍會受 DRAM 結構與控制器行為影響。

    這樣就比較完整。

    DRAM 的 3 個核心特徵

    最容易混淆的地方

    Q1：DRAM 是不是就是 RAM？

    不完全是。

    RAM 是大類，常見有：

    • DRAM(dynamic RAM)
    • SRAM(static RAM)

    其中：

    • DRAM 常做主記憶體
    • SRAM 常做快取記憶體(cache)

    因為 SRAM 比較快，但更貴、密度更低；DRAM 比較慢，但便宜、容量大，所以適合拿來當主記憶體。 (TechTarget)

    Q2：既然 DRAM 比較慢，為什麼不用 SRAM 當主記憶體？

    因為成本和容量。

    你可以想成：

    • SRAM 像超高級置物櫃：快，但很貴，而且做不大
    • DRAM 像一般大倉儲櫃：慢一點，但便宜很多，容量可以做很大

    所以電腦才會有階層：

    • 暫存器(register)
    • 快取(cache, 多半 SRAM)
    • 主記憶體(main memory, DRAM)
    • SSD / HDD

    快取記憶體

    講解

    這張圖在講什麼

    這張投影片在回答一個核心問題：

    為什麼 CPU(中央處理單元) 不直接一直去用 DRAM(動態隨機存取記憶體)，中間還要多一層 cache memory(快取記憶體)？

    答案是：

    因為 CPU 很快，DRAM 相對慢。 所以我們在 CPU 和 DRAM 之間放一個更小、但更快的記憶體，當作緩衝區，這就是 cache memory(快取記憶體)。投影片內容和課本後面關於 SRAM/DRAM 的整理一致：快取通常使用 SRAM，而主記憶體通常使用 DRAM。 (TechTarget)

    先用生活化例子理解

    你可以把它想成：

    • CPU = 正在做事的人
    • cache = 桌面
    • DRAM = 書櫃

    如果你每做一步都要跑去書櫃拿資料，會很慢。 所以你會把最近常用的資料先放桌上。

    這樣：

    • 桌面很近，所以拿東西很快
    • 但桌面很小，放不了太多東西
    • 書櫃很大，但拿東西比較慢

    這就是 memory hierarchy(記憶體階層) 的概念： 越靠近 CPU，速度越快、容量越小、成本越高。 (btu.edu.ge)

    投影片每一句在說什麼

    1.「處理器內部有另一類記憶體──快取記憶體」

    意思是：

    除了我們平常說的 RAM(主記憶體) 以外，CPU 裡面或很靠近 CPU 的地方，還有一種專門加速用的記憶體，叫 cache memory(快取記憶體)。

    它不是拿來大量存資料的，主要是拿來放：

    • 最近剛用過的資料
    • 很快又可能會再用到的資料
    • 常用指令
    2.「快取記憶體是做為 DRAM 記憶體緩衝儲存器的小而快的記憶體」

    這句最重要。

    拆開看：

    • 小 (small)：容量不大
    • 快 (fast)：存取速度很高
    • 緩衝儲存器 (buffer)：幫 CPU 和 DRAM 之間做中介

    也就是說，cache 不是要取代 DRAM， 而是要讓 CPU 不用每次都直接碰 DRAM。

    3.「快取以 SRAM 建構」

    這句是在講技術實作。

    快取通常用 SRAM(靜態隨機存取記憶體)。 主記憶體通常用 DRAM(動態隨機存取記憶體)。這也是你這份教材後面幾頁明確寫到的內容。

    4.「SRAM 較 DRAM 快，但線路較大，因此也較貴」

    這句是在講取捨 (trade-off)。

    你可以直接記成：

    • SRAM：快、貴、大、容量小
    • DRAM：慢、便宜、密度高、容量大

    原因很簡單：

    • SRAM 為了讓資料保持得更穩、更快讀寫，電路結構比較複雜
    • DRAM 每個 bit(位元) 的實作比較省空間，所以能做得更大、比較便宜，但需要刷新(refresh)

    因此才會形成現在的分工：

    • Cache → SRAM
    • Main Memory(主記憶體) → DRAM (purestorage.com)

    你最容易考的重點整理

    快取記憶體的功能

    把 CPU 常用的資料與指令 暫時放在更近的地方，減少到 DRAM 取資料的次數，提升整體效能。(TechTarget)

    為什麼快

    因為它通常用 SRAM，不需要像 DRAM 那樣持續 refresh(刷新)。 (GeeksforGeeks)

    為什麼小

    因為 SRAM 面積較大、成本較高，不能像 DRAM 一樣做很大容量。 (purestorage.com)

    為什麼不能直接全部都用 SRAM

    因為太貴，而且太占晶片面積。 如果整台電腦主記憶體都用 SRAM，成本會非常高，不實際。(btu.edu.ge)

    Q：暫存器是SRAM嗎，還是其他種

    結論先講

    一般課本語境下，暫存器(register)通常不直接說成 SRAM。 更精確地說：

    • 單一暫存器(register) 通常是由 flip-flop(正反器) 或 latch(鎖存器) 組成。(cse.iitk.ac.in)
    • SRAM 也是用類似雙穩態(bistable)電路儲存資料，但它通常是做成大規模記憶體陣列(memory array)，常見用途是 cache(快取)。(維基百科)
    • 所以在計算機結構裡，最常見的講法是： register 用 flip-flop；cache 用 SRAM；main memory(主記憶體) 用 DRAM。 (cse.iitk.ac.in)

    為什麼很多人會搞混

    因為 SRAM 本身就是用 flip-flop 類型的儲存概念 來保存位元，所以你會看到有些資料寫：

    SRAM 用在 cache 和 high-speed registers

    這句話不算完全錯，但對初學者容易混淆。(Lenovo)

    更精確的理解是：

    • register：偏向 CPU 內部少量、超高速、直接參與運算控制的儲存單元
    • SRAM：偏向大量排列成陣列的高速記憶體結構

    就像：

    • 單一抽屜 = register
    • 一整排很多抽屜的櫃子 = SRAM array

    兩者都能存東西，但設計目的與組織方式不同。

    ISA vs ABI

    • ISA：規定 CPU 提供哪些底層機器功能，例如 instruction(指令)、register(暫存器)、addressing mode(定址方式)。

    • ABI：規定 編譯好的程式，要怎麼一致地使用這些功能，例如參數放哪裡、回傳值放哪裡、stack(堆疊) 怎麼排、型別大小怎麼定。

    • ABI = 大家約好按鈕要怎麼按，才不會互相搞錯

    • ISA (Instruction Set Architecture，指令集架構)：定義 mov、add、call、syscall 這些 instruction(指令) 是什麼意思，還有 rax、rbx 這些 register(暫存器) 以及 addressing mode(定址方式) 怎麼用。x64 官方文件也明講它擴充了 x86 的暫存器與 addressing modes(定址模式)，而 Intel 的指令手冊則專門描述處理器的 instruction set(指令集)。 (Microsoft Learn)
    • ABI (Application Binary Interface，應用程式二進位介面)：定義「參數放哪裡、回傳值放哪裡、stack(堆疊) 怎麼用」，也就是 binary(二進位) 層的合作規則。Microsoft 的 x64 ABI 文件明確說它涵蓋 calling convention(呼叫慣例)、type layout(型別配置)、stack 與 register 使用等內容。 (Microsoft Learn)

    例子 1：mov / add 這種，就是 ISA 的範圍

    看這段 x64 assembly(組合語言)：

    mov rax, [rbx]

    add rax, 5

    這裡：

    • mov 是「搬資料」的指令
    • add 是「加法」的指令
    • rax、rbx 是暫存器
    • [rbx] 代表用 rbx 當位址去抓記憶體資料

    這些都屬於 ISA，因為它在回答：

    CPU 到底認得哪些指令？ 這些指令怎麼解讀？ 暫存器和定址方式有哪些？

    Microsoft 的 x64 架構說明甚至直接給了類似例子：mov rax, [rbx] 代表把從 rbx 指向位置開始的 8 bytes 載入到 rax；也提到 x64 新增了 rip-relative addressing(相對於指令指標的定址) 等模式。 (Microsoft Learn)

    例子 2：call 還不夠，參數放哪裡才是 ABI

    假設你有這個 C：

    sum(10, 20, 30, 40, 50);

    編譯後一定會有某種 call 指令，但光有 call 還不夠。 還要先決定：

    • 第 1 個參數放哪個 register？
    • 第 2 個參數放哪裡？
    • 第 5 個參數是不是要放 stack？
    • 回傳值要去哪裡拿？

    這就是 ABI。

    在 Windows x64 ABI

    前四個整數或指標參數放在：

    • RCX
    • RDX
    • R8
    • R9

    剩下的參數放 stack，整數或指標回傳值放在 RAX。 (Microsoft Learn)

    在 System V AMD64 ABI（Linux 常見的 user-space 慣例）

    整數參數依序使用：

    • %rdi
    • %rsi
    • %rdx
    • %rcx
    • %r8
    • %r9

    你看，同樣都是 x64 這個 ISA，call 這條指令的意思沒有變，但「參數要放哪裡」這件事可以因 ABI 不同而不同。這正是 ISA 與 ABI 的差異。 (Microsoft Learn)

    例子 3：syscall 是最像你直覺的例子

    這個例子超好記。

    syscall 這條指令本身，屬於 ISA

    因為它是 CPU 提供的一條 instruction(指令)。System V AMD64 ABI 文件也把 syscall 列成 AMD64 程式可期待的處理器特性之一。

    但「怎麼用 syscall」的細節，屬於 ABI

    Linux 的 AMD64 慣例規定：

    • system call number(系統呼叫編號) 放在 %rax
    • 參數放在 %rdi, %rsi, %rdx, %r10, %r8, %r9
    • 回傳值放回 %rax
    • syscall 之後 %rcx 和 %r11 會被破壞

    所以：

    • syscall 這條指令存在 → ISA
    • 用 syscall 時，編號和參數塞哪些暫存器 → ABI

    這個例子最適合拿來分辨兩者。

    Q：用C++舉例一個會一個呼叫CPU動作的程式碼，講解ISA、ABI

    先修正一句話

    嚴格來說，C++ 不是「呼叫 CPU 動作」，而是：

    C++ 程式先被 compiler(編譯器) 轉成 machine code(機器碼)，CPU 再去執行那些 instruction(指令)。

    所以我們比較精確的說法會是：

    用一段 C++，看它最後會變成哪些 CPU 指令，順便分清楚哪些是 ISA、哪些是 ABI。

    C++ 範例

    先看一個最小、最好懂的例子：

    long long add(long long a, long long b) {

    return a + b;

    }

    int main() {

    return (int)add(10, 20);

    }

    這段程式做的事情很單純：

    1. main() 呼叫 add(10, 20)
    2. add() 把兩個數字加起來
    3. 結果回傳給 main()

    它可能對應成這種 x86-64 組語

    以下是簡化示意版，不是保證每個編譯器都逐字一樣，但很適合拿來理解：

    main: mov rcx, 10 mov rdx, 20 call add ; 回傳值現在在 rax add: mov rax, rcx add rax, rdx ret

    先只看「這段組語在做什麼」

    mov rcx, 10

    把數值 10 放進 rcx 暫存器。

    mov rdx, 20

    把數值 20 放進 rdx 暫存器。

    call add

    跳去執行 add，而且會先保存「等等要回來哪裡」。

    mov rax, rcx

    在 add 裡，把第一個參數先搬到 rax。

    add rax, rdx

    把第二個參數加進去。

    ret

    回到呼叫 add 的地方。

    這裡哪個是 ISA？

    ISA (Instruction Set Architecture，指令集架構)

    ISA 在這個例子裡，管的是：

    • mov
    • add
    • call
    • ret
    • rax、rcx、rdx 這些 register(暫存器)
    • 指令怎麼解讀、怎麼作用

    Intel 官方文件就是把這些內容放在 instruction set reference(指令集參考) 裡；例如 ADD 的定義就是把來源運算元和目的運算元相加，再把結果存回目的地。(英特爾)

    另外，Microsoft 的 x64 架構說明也明確提到像 mov rax, [rbx] 這種指令如何搬資料，並指出 jmp、call、push、pop 這類指令在 x64 會隱含使用 instruction pointer(指令指標) 與 stack pointer(堆疊指標)。(Microsoft Learn)

    所以在這段程式裡：

    • mov 是 ISA
    • add 是 ISA
    • call / ret 是 ISA
    • rax / rcx / rdx 是 ISA 提供的暫存器概念

    你可以把它想成：

    ISA 在回答：CPU 到底有哪些按鈕可以按？每個按鈕按下去會發生什麼事？

    這裡哪個是 ABI？

    ABI (Application Binary Interface，應用程式二進位介面)

    ABI 在這個例子裡，管的是：

    • 為什麼第一個參數放 rcx
    • 為什麼第二個參數放 rdx
    • 為什麼回傳值放 rax
    • 呼叫函式前後，哪些暫存器可以被改、哪些要保留

    以 Windows x64 ABI 為例，Microsoft 文件明確規定：

    • 整數參數會放在 RCX、RDX、R8、R9
    • 可放入 64 位的純量回傳值會透過 RAX 傳回
    • RAX、RCX、RDX、R8、R9、R10、R11 等屬於 volatile(揮發性) 暫存器，也就是函式呼叫時可以被覆寫 (Microsoft Learn)

    所以在這段程式裡：

    • a 放進 rcx → ABI
    • b 放進 rdx → ABI
    • 結果放進 rax → ABI

    你可以把它想成：

    ABI 在回答：大家都用同一顆 CPU 時，呼叫函式要照什麼規矩來放參數和拿結果？

    為什麼這個例子很好？

    因為它剛好能把兩件事完全分開：

    同一段程式的「CPU 指令內容」

    這是 ISA

    例如：

    • mov 的意思是搬資料
    • add 的意思是做加法
    • call 的意思是呼叫函式
    • ret 的意思是返回
    同一段程式的「函式呼叫規矩」

    這是 ABI

    例如：

    • 第 1 個參數為何在 rcx
    • 第 2 個參數為何在 rdx
    • 為何答案從 rax 拿

    看這段：

    mov rcx, 10 mov rdx, 20 call add

    是在問：

    從 ABI 角度看

    是在問：

    1. 揮發性記憶體(Volatile Memory)

    意思是：

    只要一斷電，資料就沒了。

    投影片舉的例子是 DRAM(Dynamic RAM，動態隨機存取記憶體)。這也是一般電腦裡常說的「記憶體條」。課件也明確寫到，主記憶體通常就是用 DRAM 組成。

    官方資料也一致：Intel 把 DRAM 描述成電腦的短期工作記憶(short-term working memory)，電源關掉後資料會消失；Samsung 也把 flash memory 與 DRAM/SRAM 對照，指出 DRAM/SRAM 斷電後不保留資料。(英特爾)

    你可以把它想成：

    • 桌面
    • 你現在正在攤開的課本、計算紙、筆記

    桌面很好用、拿東西很快，但你一把桌面清空，東西就不在了。

    2. 非揮發性記憶體(Non-volatile Memory)

    意思是：

    就算斷電，資料也還在。

    投影片說這類用來保存「各次執行之間」的程式與資料，也就是你關機後，檔案、照片、作業還會留著。

    官方資料也一致：Samsung 將 flash memory 定義為斷電後仍能保存資料的半導體記憶體；Intel 也把 non-volatile data 描述為關機後仍會存在的長期資料。(Samsung Semiconductor Global)

    你可以把它想成：

    • 書櫃 / 倉庫
    • 你把檔案收進去，明天再來還在

    第一張圖裡最重要的兩個名詞

    主記憶體(Main Memory)

    這是在講：

    CPU 現在工作時直接使用的主要工作區。

    投影片寫得很直接：主記憶體用來保存正在執行中的程式與資料，現在的電腦通常用 DRAM 做成。

    所以主記憶體不是拿來「長期保存」的，而是拿來「讓 CPU 目前能快速工作」的。

    次記憶體(Secondary Storage)

    這是在講：

    長期保存資料的地方。

    投影片說它是用來保存各次執行之間的程式與資料，而且屬於非揮發性。

    典型例子就是：

    • HDD(Hard Disk Drive，傳統硬碟)
    • SSD(Solid State Drive，固態硬碟)
    • USB 隨身碟
    • 記憶卡

    • 非揮發性
    • 用旋轉碟片
    • 表面有磁性材料
    • 存取速度比主記憶體慢很多

    你可以把 HDD 想成：

    • 容量大
    • 便宜
    • 但因為有機械轉動，所以慢一些
    2. 快閃記憶體(Flash Memory)

    投影片把快閃記憶體列成：

    • 非揮發性
    • 半導體記憶體
    • 比 DRAM 慢，但比磁碟快

    Samsung 的半導體字典也把 flash memory 定義成：斷電後仍保存資料的 non-volatile memory，常用於手機、USB drive、儲存裝置。(Samsung Semiconductor Global)

    • SSD
    • USB 隨身碟
    • 記憶卡
    • 手機內部儲存

    最容易搞混的地方

    1. 「記憶體」和「儲存裝置」不是同一件事

    日常講話常把它們混在一起，但在計算機結構裡要分很清楚：

    • RAM / DRAM → 主記憶體
    • HDD / SSD / USB → 次記憶體

    也就是說：

    RAM 不是拿來長期存檔的。 SSD/HDD 也不是 CPU 當下最主要的工作桌面。

    2. 程式平常放在硬碟/SSD，但執行時通常要進 RAM

    這點你的課件其實也有寫到：電腦執行軟體前，首先要把可執行碼載入主記憶體。

    生活化一點講：

    • 你的作業檔平常放在 SSD/HDD
    • 你一打開 Word
    • 作業內容和程式的一部分會被載入 RAM
    • CPU 才能快速處理

    所以：

    硬碟/SSD 像倉庫，RAM 像工作桌。

    3. 「非揮發性」不等於「不能改」

    這也很常被混淆。

    • Volatile / Non-volatile 講的是：斷電後資料在不在
    • Read-only / Writable 講的是：能不能寫入修改

    例如：

    • Flash memory 是 非揮發性，但可以寫入
    • ROM(Read Only Memory) 是非揮發性，而且通常不拿來當一般可寫工作區

    這點從 Samsung 對 ROM 與 flash 的定義也能看出來：ROM 與 flash 都屬於 non-volatile，但用途和可改寫方式不同。(Samsung Semiconductor Global)

    一句話版

    • 次記憶體 = 慢一些、拿來長存、斷電不會忘，像 HDD/SSD/隨身碟
    二句話版
    • CPU 執行程式時，主要在 主記憶體(Main Memory) 上工作。
    • 想讓資料關機後還在，就要放到 非揮發性的次記憶體(Secondary Storage)。

    社群上常見的卡點

    很多人在討論區第一次學這段時，最容易卡在這句：

    「既然 SSD 很快，為什麼它不能直接當 RAM？」

    • 延遲(latency)

    Q：電容是啥

    電容(capacitance) 是什麼？

    最簡單地說：

    電容就是「一個系統有多容易把電荷(charge，電荷)分開存起來」的能力。 它也可以理解成：在一定電壓(voltage，電壓)下，能存多少電荷。 數學上常寫成 C = Q / V，也就是電容 = 電荷 ÷ 電壓。(Encyclopedia Britannica)

    用生活化方式想

    你可以把它想成一個「裝電的容器」：

    • Q(charge，電荷)：像裝進去的水量
    • V(voltage，電壓)：像把水擠進去需要的壓力
    • C(capacitance，電容)：像這個容器有多好裝

    所以：

    • 電容大 → 同樣電壓下，可以存比較多電荷
    • 電容小 → 存一點電荷，電壓就升很快。(Physics LibreTexts)

    它和電容器(capacitor，電容器)的關係

    • 電容(capacitance) 是一種「能力、性質」
    • 電容器(capacitor) 是實際的元件

    就像：

    • 容量 是性質
    • 杯子 是物體

    電容器會把正負電荷分別存到兩端，並把能量儲存在電場(electric field，電場) 裡。(Encyclopedia Britannica)

    單位是什麼？

    電容的 SI 單位是 farad(F，法拉)，而且 1 farad = 1 coulomb per volt = 1 C/V。(超物理學)

    為什麼觸控螢幕會提到電容？

    因為電容式觸控(capacitive touch，電容式觸控)就是在測「電容有沒有變」。 你的手指碰到螢幕時，會改變螢幕表面的電場分布，因此讓某些位置的電容改變，系統就知道你碰了哪裡。這也是你剛剛那頁投影片在講的核心。這裡我是在根據電容的物理定義，連回觸控螢幕的工作原理做推論。(Encyclopedia Britannica)

    Q：簡單講解良率是啥

    良率(yield) 是什麼？

    良率就是：做出來的產品裡面，有多少比例是「好的、能正常用的」。

    最簡單的公式：

    良率 = 良品數 ÷ 總生產數

    例如：

    • 做了 100 顆晶片
    • 其中 85 顆正常
    • 那良率就是 85%

    這和半導體製造常見的定義一致：yield 通常就是晶圓上或整個製程中，可正常工作的晶片所占比例。(ASML)

    放到這張投影片裡怎麼看？

    投影片寫：

    • 一片晶圓可能切出很多顆晶片
    • 但不是每一顆都一定成功
    • 有些會因為製程缺陷(defect，缺陷)壞掉
    • 最後通過測試、能封裝出貨的比例，就是良率

    所以這頁的 yield 17/20 或 85%，意思就是：

    • 原本有 20 顆
    • 其中 17 顆是好的
    • 所以良率 = 17 ÷ 20 = 85%

    你可以把它想成

    像考試一樣：

    • 全班 20 個人做作品
    • 最後有 17 個作品合格
    • 那這次作品的「合格率」就是 85%

    在晶片工廠裡，這個「合格率」就是良率(yield)。

    為什麼良率很重要？

    因為：

    • 良率高 → 壞掉的少 → 成本比較低
    • 良率低 → 壞掉的多 → 很浪費

    所以半導體製造很重視提高良率；良率提升，通常代表能交付更多正常晶片、減少報廢(scrap，報廢)並降低成本。(Semiconductor Engineering)

    一句話記法

    良率就是「做出來的產品中，有幾成是合格可用的」。

    先說一個總觀念

    我先依你這組投影片的脈絡整理，所以這是課內版本。有些名詞在業界會再分得更細，但你現在先把這一章的主線抓穩最重要： 效能看的是時間與工作量，不是只看 GHz。 這也是 Berkeley 的經典架構課在教效能時的核心框架：如果我們關心單一工作的快慢，就看 response time / execution time；如果關心單位時間做多少工作，就看 throughput / bandwidth。

    專業名詞整理

    0. 中央處理器

    就是指 CPU
    中央處理器(Central Processing Unit, CPU，中央處理器)

    1. Performance(效能)

    整體來說就是「電腦做事有多快、多有效率」。 在這章裡，若我們主要關心一個工作多久做完，就可以把效能理解成：

    Performance = 1 / Execution Time

    也就是說，執行時間越短，效能越高。

    2. System Performance(系統效能)

    看的是整個系統完成一個程式或工作時的表現。 它比較接近你投影片裡講的「從開始到結束」的角度，也就是會把 CPU 以外的等待、I/O(input/output，輸入輸出) 等因素一起考慮進去。投影片把這件事放在 elapsed time(經過時間) 的脈絡裡理解是合理的；Oracle 也把 wall-clock time(牆鐘時間) 視為這種外在經過時間。(Oracle Docs)

    3. CPU Performance(CPU 效能)

    看的是 CPU 真正花在執行這個程式上的時間，不把等待 I/O 或其他程式插進來的時間算進去。這通常就是 CPU time(CPU 時間) 的脈絡。(EECS Berkeley)

    4. Elapsed Time(經過時間) / Wall-clock Time(牆鐘時間)

    就是你拿碼表從程式開始按，到程式結束停下來的時間。 它會包含 CPU 運算，也可能包含等待磁碟、網路、I/O、作業系統排程等等待時間。Oracle 文件把 wall time 明確稱為通常的 wall-clock time；Ask TOM 也明講 elapsed time 會包含 CPU time 加上 waits。(Oracle Docs)

    5. Response Time(反應時間)

    完成一個工作所需的時間。 在這章裡，它常和 Execution Time(執行時間)、有時也和 Latency(延遲) 放在同一類概念來理解，也就是「一件事多久完成」。

    6. Execution Time(執行時間)

    程式或任務從開始到完成所花的時間。 在 Berkeley 架構課裡，response time、execution time、latency 常被放在同一組概念來講。(EECS Berkeley)

    7. Latency(延遲)

    比較偏工程語感的說法，意思也是「完成一件事要多久」。 你這組投影片主要用的是 response time / execution time，但如果之後課本或別的資料看到 latency，先把它當成同一掛即可。(EECS Berkeley)

    8. Throughput(處理量)

    單位時間內完成多少工作。 例如一台伺服器每秒能處理幾筆請求，這就是 throughput。Berkeley 課程直接把 throughput 定義成 tasks completed per unit time。(EECS Berkeley)

    9. Bandwidth(頻寬)

    在你這章投影片裡，bandwidth 幾乎是跟 throughput 放在一起講，都是「單位時間能做多少」。 但你要知道，更嚴格地說，bandwidth 常偏向「最大傳輸能力」，throughput 常偏向「實際完成量」。這章先把它們視為近似同義就夠了。

    10. User CPU Time(使用者 CPU 時間)

    程式在 user mode(使用者模式) 下，真正佔用 CPU 執行的時間。 Linux 手冊和 Oracle 文件都把它定義成在 user mode 跑在 CPU 上的時間。(man7.org)

    11. System CPU Time(系統 CPU 時間)

    程式在 kernel mode(核心模式 / 系統模式) 下，由作業系統代它做事時用掉的 CPU 時間，例如 system call(系統呼叫)。(man7.org)

    12. CPU Time(CPU 時間)

    就是 CPU 真正在工作、替這個程式執行的時間。 它常被拆成：

    • user CPU time
    • system CPU time

    也就是：

    CPU time = user CPU time + system CPU time。(EECS Berkeley)

    13. Clock Signal(時脈訊號)

    數位電路的「節拍器」。 電腦硬體靠這個規律訊號來決定什麼時候更新狀態、做下一步。你這組投影片後面所有 clock period、clock rate、CPI 幾乎都建立在這個概念上。(EECS Berkeley)

    14. Clock Cycle(時脈週期 / 時脈循環)

    時脈的一次循環，也可想成一次 tick(滴答)。 CPU 不是「每個指令都一定只花一個 cycle」，有些指令可能一個 cycle 做完，有些會花很多個 cycle。Intel 也明講：有時一個週期可完成多個指令，有時一個指令要跨多個週期。(Intel)

    15. Clock Period / Clock Cycle Time(時脈週期時間)

    一個時脈週期有多長，例如 250 ps(picoseconds，皮秒)。 它和 clock rate 是倒數關係。(EECS Berkeley)

    16. Clock Rate / Clock Speed / Frequency(時脈速度 / 時脈頻率)

    每秒有多少個 clock cycle。 常見單位是 Hz、MHz、GHz。Intel 的定義就是 cycles per second，GHz 代表每秒十億個 cycles。(Intel)

    17. Inverse Relationship(倒數關係)

    這是在講：

    Clock Rate = 1 / Clock Period Clock Period = 1 / Clock Rate

    所以頻率越高，單一週期越短。(EECS Berkeley)

    18. Instruction Count, IC(指令數)

    一個程式執行時，總共跑了多少條指令。 注意是「實際執行的指令總數」，不是原始碼幾行。(EECS Berkeley)

    19. 中央處理器時脈數 Clock Cycles for a Program(程式所需時脈數)

    某個程式跑完總共用了多少 clock cycles。 投影片中的「中央處理器時脈數」講的就是這個概念。(EECS Berkeley)

    20. CPI(Cycles Per Instruction，每指令平均時脈週期數)

    平均來說，一條指令要花幾個 cycle。 公式是：

    CPI = Clock Cycles / Instruction Count。Berkeley 的課件也是這樣定義。(EECS Berkeley)

    21. Instruction Class(指令類別)

    不同類型的指令，可能有不同的 CPI。 例如投影片範例中的 A、B、C 三種指令類別，就是在說： 不是所有指令成本都一樣。(EECS Berkeley)

    22. CPU Performance Equation(CPU 效能計算式)

    這是這一章最重要的公式：

    CPU Time = Instruction Count × CPI × Clock Cycle Time

    因為 Clock Cycle Time = 1 / Clock Rate，所以也可寫成：

    CPU Time = (Instruction Count × CPI) / Clock Rate。(EECS Berkeley)

    23. Relative Performance(相對效能)

    拿兩台機器互相比較快慢。 如果 X 比 Y 快 n 倍，則：

    Performance(X) / Performance(Y) = n 也等於 Execution Time(Y) / Execution Time(X) = n。

    24. “n Times Faster”(快 n 倍)

    這個很容易算反。 如果 A 跑 10 秒、B 跑 15 秒，則：

    A 比 B 快 15 / 10 = 1.5 倍

    不是用 10/15。因為快慢比要用對方時間除以自己時間。

    25. GHz / MHz / ps
    • GHz(gigahertz，GHz)：每秒十億個週期
    • MHz(megahertz，MHz)：每秒一百萬個週期
    • ps(picoseconds，皮秒)：10^-12 秒，常用來表示很短的 clock period。(EECS Berkeley)

    幫你整理重點

    重點 1：不要只看 GHz

    時脈速度(clock rate) 很重要，但不是唯一答案。Intel 也直接提醒：不同 CPU 設計處理指令的方法不同，所以不能只用 clock speed 判斷全部效能。(Intel)

    重點 2：評估「快不快」要先問你在看哪一種快

    如果你在乎的是「這個程式多久跑完」，看的是 response time / execution time。 如果你在乎的是「一秒能做多少件事」，看的是 throughput / bandwidth。這兩者不一定同時一起變好。

    重點 3：CPU time 和 elapsed time 不一樣
    • Elapsed time：整體碼表時間，含等待
    • CPU time：CPU 真正在幫你跑的時間
    • CPU time = user CPU time + system CPU time。(asktom.oracle.com)
    重點 4：這章核心公式一定要背

    CPU Time = Instruction Count × CPI × Clock Cycle Time 這代表要讓程式更快，有三個方向：

    • 降低指令數
    • 降低 CPI
    • 降低 clock cycle time（也就是提高 clock rate）(EECS Berkeley)
    重點 5：CPI 低，不一定就一定比較快

    這是學生最常卡的點。 因為真正決定 CPU time 的是 Instruction Count、CPI、Clock Cycle Time 三者相乘。某個設計雖然 CPI 比較低，但如果它指令數變多，或 clock period 變長，最後還是可能比較慢。這也是你後面「比較程式碼片斷」那幾頁在示範的核心思路。(EECS Berkeley)

    重點 6：比較兩段程式碼，不能只看「誰指令少」

    你要看的是：

    總 clock cycles = Σ(每類指令數 × 該類 CPI)

    所以某段程式雖然指令比較多，但如果用到更多低 CPI 的指令，最後總 cycles 反而可能更少，因此更快。這正是你投影片中序列 2 比序列 1 快的原因。(EECS Berkeley)

    重點 7：相對效能很容易算反

    如果題目問「A 比 B 快幾倍」，你就用：

    Execution Time(B) / Execution Time(A)

    誰比較快，誰放分母。

    你現在最該背的 4 句話

    1. Performance 跟 time 成反比。
    2. CPU Time = Instruction Count × CPI × Clock Cycle Time。
    3. Clock Rate = 1 / Clock Period。
    4. 比較快慢不能只看 GHz，也不能只看 CPI，要看整個公式。

    這幾題其實都在考同一件事

    你最該背的公式

    公式裡各英文單字翻譯

    • CPU Time：中央處理器時間

    • Instruction Count：指令數

    • CPI (Cycles Per Instruction)：每指令平均時脈週期數

    • Clock Cycle Time：時脈週期時間

    • Clock Cycles：時脈數／時脈週期數

    • Clock Rate：時脈速度／時脈頻率

    • Performance：效能

    • Execution Time：執行時間
