    作業二

    Part 1：Multiply-Add Designs（乘法與加法電路）

    這是 HW2 的第一個實驗，也是理解整份作業很重要的起點。

    這一部分最重要的觀念是：數學上等價的運算式，寫成不同 RTL（Register Transfer Level）之後，合成出的硬體可能有不同的面積、速度與功耗。

    依據老師《HW2_pipelined add_sub_multiplier》第 1 頁、助教《HDL Homework2 補充說明》第 6 頁，以及老師 10/06 的上課逐字稿，我們從最基本的原理開始。

    1.1 這一題到底要我們做什麼？

    老師給了兩種數學寫法：

    設計 A：Multiply-Add

    \[
d=a\times c+b\times c 
\]

    設計 B：Common Factor Extraction（提出公因數）

    \[
d=(a+b)\times c 
\]

    利用數學的 Distributive Property（分配律），我們知道：

    \[
ac+bc=(a+b)c 
\]

    例如，假設 \(a=2\)、\(b=3\)、\(c=4\)：

    • 設計 A：\(2\times4+3\times4=8+12=20\)
    • 設計 B：\((2+3)\times4=5\times4=20\)

    計算結果相同。

    但是，Verilog 不是只負責把數學算式算出答案，它描述的是實際要做出什麼硬體。

    這是本題真正要研究的問題。

    1.2 第一種寫法：先乘法，再加法

    老師提供的原始程式：

    module multiply_add (
    input [7:0] a, b, c,
    output [15:0] d
);
    assign d = a*c + b*c;
endmodule

    先了解這幾行：

    • input [7:0]：a、b、c 各是 8-bit 輸入。
    • output [15:0]：d 是 16-bit 輸出。
    • assign：Continuous Assignment（連續指定），用來描述組合邏輯。
    • a*c + b*c：指定電路需要完成的算術運算。

    這裡沒有 always @(posedge clk)，也沒有暫存器，因此它是 Combinational Circuit（組合電路）。

    依照老師註解的概念，這種寫法可以想成：

    a × c

    Multiplier 1

    b × c

    Multiplier 2

    加法器（Adder）

    將兩個乘積相加

    輸出 d

    這個架構有兩個重要特點：

    第一，硬體面積可能比較大。

    因為需要處理兩個乘法運算。老師在 10/06 課堂特別提到，Multiplier（乘法器）通常比 Adder（加法器）昂貴，也就是一般會占用更多硬體資源。

    第二，兩個乘法可以平行執行。

    a*c 和 b*c 彼此沒有資料相依性，所以不必等其中一個算完才開始另一個。

    等兩個乘積完成，再進行加法。

    這就是 Parallelism（平行運算）的概念。

    1.3 第二種寫法：先加法，再乘法

    老師提供的第二個程式：

    module multiply_add_common_factor (
    input [7:0] a, b, c,
    output [15:0] d
);
    assign d = (a+b)*c;
endmodule

    這次，我們先把 a 和 b 相加，再乘上 c。

    a + b

    Adder

    (a+b) × c

    Multiplier

    輸出 d

    這裡有什麼差別？

    原本的算式描述了兩個乘法，現在只剩下一個乘法。

    因此，直覺上可以預期它使用的面積會比較小。

    但它也有一個缺點：

    乘法器必須等待加法器的結果。

    這叫做 Data Dependency（資料相依性）。

    即使只剩下一個乘法器，整條運算路徑不一定會更快。

    1.4 為什麼硬體變少，速度卻可能變慢？

    先理解 Critical Path（關鍵路徑）的概念。

    Critical Path 是電路中最慢、決定整體 Timing Performance 的路徑。

    對設計 A，直觀上的路徑是：

    \[
T_A\approx T\_{\mathrm{mul}}+T\_{\mathrm{add}} 
\]

    但兩個乘法器可以平行執行，並不是：

    \[
2T\_{\mathrm{mul}}+T\_{\mathrm{add}} 
\]

    對設計 B，路徑則是：

    \[
T_B\approx T\_{\mathrm{add}}+T\_{\mathrm{mul}} 
\]

    你可能會注意到，這兩個粗略式子看起來很像。

    那為什麼真正的 Delay 還是不同？

    因為這只是概念模型。實際合成還受到運算位寬、進位傳遞、邏輯閘結構、負載及工具最佳化影響。兩個運算順序不同的電路，並不保證有相同延遲。

    因此，到底哪個電路比較快，必須看 Design Compiler 的實際 Timing Report，而不是只看乘法器數量。

    1.6 讀懂 Timing Report：兩個設計都通過了嗎？

    有，而且都符合助教指定的 1 ns Timing Constraint。

    Timing 指標 設計 A 設計 B
    Data Arrival Time 0.500517 ns 0.650433 ns
    Required Time 1.000000 ns 1.000000 ns
    Slack +0.499483 ns +0.349567 ns
    結果 MET MET

    這裡你需要認識一個重要公式：

    \[
\text{Slack}=\text{Required Time}-\text{Arrival Time} 
\]

    以設計 A 為例：

    \[
1.000000-0.500517=0.499483\text{ ns} 
\]

    因為 Slack 是正數，所以代表路徑符合這次的 Timing Constraint。

    1.7 一個很容易忽略的問題：Bit Width（位元寬度）

    這兩個數學算式雖然等價，但在 Verilog 中還要考慮訊號的位元寬度。

    老師給的是 8-bit 輸入、16-bit 輸出。如果你額外建立一個 8-bit 暫存結果來存放 a+b，當加法結果超過 255 時，就可能遺失進位。

    例如：

    \[
200+200=400 
\]

    400 需要 9 bits 才能完整表示，8-bit 無法保存全部結果。

    這個例子是在說明位元寬度風險，並不代表老師原本的 (a+b)*c 一定會把加法截斷成 8 bits；Verilog 運算式的實際寬度還受到運算上下文規則影響。

    這個觀念在 Part 2 會非常重要，因為你實際寫的 add_sub_1 就有 8-bit 中介變數造成的功能差異。

    1.8 Part 1 的核心結論

    這一部分你應該掌握四件事：

    1. RTL 是用來描述硬體運算，不只是數學公式。
    2. 乘法器通常需要比較多的硬體面積。
    3. 使用較少的運算元件，不一定代表 Critical Path 較短。

    2.1 這一題要做什麼？

    我們要設計一個可以執行加法與減法的電路。

    有三個輸入與一個輸出：

    訊號 位元寬度 用途
    a 8 bits 第一個運算數
    b 8 bits 第二個運算數
    s 1 bit 控制加法或減法
    d 16 bits 運算結果

    老師規定：

    \[
d= \begin{cases} a+b,&s=1\\\ a-b,&s=0 \end{cases} 
\]

    例如，假設 \(a=10\)、\(b=3\)：

    當 s=1：

    \[
d=10+3=13 
\]

    當 s=0：

    \[
d=10-3=7 
\]

    所以 s 就像一個開關，決定使用哪一種運算。

    這裡需要認識兩個硬體元件：

    • Adder（加法器）： 執行二進位加法。
    • Multiplexer，MUX（多工器）： 根據控制訊號，選擇不同的輸入資料。

    例如 2-to-1 MUX，就像鐵路轉轍器：有兩條資料路徑，根據選擇訊號決定哪一條通往輸出。

    2.2 第一種寫法：add_sub_1

    老師的原始程式如下：

    module add_sub_1 (
    input [7:0] a, b,
    input s,
    output [15:0] d
);
    wire [7:0] tmp;
    assign tmp = s ? b : -b;
    assign d = a + tmp;
endmodule

    這個版本的想法很有意思：

    我們可以把減法改寫成加法。

    因為：

    \[
a-b=a+(-b) 
\]

    所以不管是加法或減法，最後都使用 a + tmp。

    差別只在 tmp 應該是 b 還是 -b。

    第一行關鍵程式
    assign tmp = s ? b : -b;

    這裡的 ? : 稱為 Ternary Operator（三元條件運算子）。

    語法：

    condition ? value_if_true : value_if_false

    因此：

    當 s=1，tmp=b。

    當 s=0，tmp=-b。

    第二行關鍵程式
    assign d = a + tmp;

    最後只描述加法運算。

    2.4 第三種寫法：add_sub_3

    老師的原始程式：

    module add_sub_3 (
    input [7:0] a, b,
    input s,
    output reg [15:0] d
);
    always @(a or b or s)
        if (s == 1)
            d = a+b;
        else
            d = a-b;
endmodule

    這裡用的是 Behavioral Modeling（行為式描述）。

    和前兩種最大的差別是：

    前兩種使用：

    assign

    第三種則使用：

    always @(a or b or s)

    表示當 a、b 或 s 發生變化時，重新執行內部敘述。

    接著透過：

    if (s == 1)
    d = a+b;
else
    d = a-b;

    選擇運算結果。

    為什麼 output reg 不代表這裡有暫存器？

    這是初學 Verilog 很容易弄錯的地方。

    reg 是傳統 Verilog 中，允許在 always 等 Procedural Block（程序區塊）內被指定值的變數型別。

    它不代表合成時一定會有 Flip-Flop（正反器）。

    這份程式沒有 posedge clk，而且 if 和 else 都會指定 d，所以描述的是 Combinational Logic（組合邏輯），不是需要時脈才能更新的暫存器。

    因此，add_sub_2 與 add_sub_3 雖然程式寫法不同，但在一般 s=0/1 的輸入下，描述相同的加減法功能。

    2.5 最重要的問題：為什麼 add_sub_1 的答案可能不一樣？

    這是我認為 Part 2 最值得徹底弄懂的觀念。

    我們先看第一種寫法：

    wire [7:0] tmp;
assign tmp = s ? b : -b;
assign d = a + tmp;

    當 s=0 時：

    tmp = -b;

    假設：

    \[
a=3,\quad b=5,\quad s=0 
\]

    數學上應該得到：

    \[
d=3-5=-2 
\]

    但是 Verilog 使用固定寬度的二進位資料，我們必須考慮 tmp 的 8-bit 限制。

    第一步：將 -5 表示成 8-bit

    電腦常使用 Two's Complement（二補數）表示負數。

    在 8-bit 下：

    \[
-5\bmod256=251 
\]

    因此：

    b   = 8'h05 = 0000 0101
-b  = 8'hFB = 1111 1011

    tmp 的確保存了 8'hFB，但是它宣告為 wire [7:0]，沒有 signed。

    因此這個位元型態若被視為 unsigned（無號整數），數值就是 251。

    第二步：計算 a + tmp
    assign d = a + tmp;

    由於 d 是 16 bits，這個加法運算在此賦值情境下會以 16-bit 寬度進行；但 已經存入 8-bit tmp 的數值，不會因此自動變回正確的 16-bit 負數。這涉及 Verilog 的 Context-Determined Expression 規則。

    所以：

    \[
3+251=254 
\]

    結果：

    add_sub_1: d = 16'h00FE
    第三步：看看 add_sub_2
    assign d = s ? a+b : a-b;

    當 s=0，直接進行 a-b。

    在這個 16-bit 輸出情境下：

    \[
3-5=-2 
\]

    以 16-bit 二補數位元型態表示：

    add_sub_2: d = 16'hFFFE

    add_sub_3 也會得到相同結果。

    比較：

    輸入條件 add_sub_1 add_sub_2 / add_sub_3
    a=3, b=5, s=1 16'h0008 16'h0008
    a=3, b=5, s=0 16'h00FE 16'hFFFE
    a=10, b=3, s=0 16'h0107 16'h0007

    你可以看到，即使 a=10, b=3 的減法結果是正數，第一種寫法仍然可能不同。

    核心原因不是減法不能用加法實作，而是 tmp 的位元寬度與 unsigned 性質，使得 8-bit 負數結果無法直接當成正確的 16-bit 減法結果。

    1. 上一題的答案

    add_sub_3 的 d 不會被合成成 Flip-Flop（正反器），而是 Combinational Logic（組合邏輯）。

    原因有三個：

    1. always @(a or b or s) 表示當輸入改變時重新計算，沒有 posedge clk 或 negedge clk。
    2. if 和 else 都有指定 d，不需要保留上一次的值。
    3. output reg [15:0] d 裡面的 reg 是傳統 Verilog 的變數型別，不代表一定會產生實體暫存器。

    所以，這個程式描述的是由控制訊號 s 選擇加減法結果的組合電路。

    記住：

    • Combinational Logic： 輸出取決於目前輸入。
    • Sequential Logic： 輸出還可能取決於先前儲存的狀態。

    這個差別正是下一部分的重要基礎。

    2. Part 3：Non-Pipelined Add/Sub-Multiply（非管線化加減乘法器）

    2.1 這一部分要做什麼？

    老師要求設計一個叫做 hw2_nonpipe 的模組，執行：

    \[
d= \begin{cases} (a+b)\times c,&s=1\\\ (a-b)\times c,&s=0 \end{cases} 
\]
    訊號 位元寬度 功能
    a、b 各 8 bits 加減法的兩個輸入
    c 8 bits 乘數
    s 1 bit 決定加法或減法
    d 16 bits 最終輸出

    例如，假設 a=7、b=3、c=5：

    • s=1：先做 \(7+3=10\)，再乘 \(5\)，得到 d=50。
    • s=0：先做 \(7-3=4\)，再乘 \(5\)，得到 d=20。

    你可以把它想成一個具有兩種模式的小型算術運算器。

    2.3 如何用 Verilog 描述這個電路？

    下面是符合老師功能要求的簡單教學示例，幫助你理解資料路徑；它不是重新讀取工作站後取得的原始 nonpipeline.v。

    module hw2_nonpipe (
    input [7:0] a, b, c,
    input s,
    output [15:0] d
);

    wire [15:0] add_sub_result;

    assign add_sub_result = s ? (a + b) : (a - b);
    assign d = add_sub_result * c;

endmodule

    第一個重點：add_sub_result

    assign add_sub_result = s ? (a + b) : (a - b);

    這行就是前一部分學過的 add_sub_2 概念：

    • s=1：使用加法。
    • s=0：使用減法。

    add_sub_result 宣告為 16 bits，可以配合 16-bit 的運算結果，不會像前面 add_sub_1 那樣先把負數結果存進一個 8-bit unsigned 暫存訊號。

    第二個重點：乘法

    assign d = add_sub_result * c;

    將剛才選出的加減法結果乘上 c。

    此處 d 是 16 bits，因此超過 16-bit 可表示範圍的結果仍可能截斷。助教允許這次 Testbench 不處理溢位等特殊情況。

    第三個重點：沒有 always @(posedge clk)

    整個設計只使用 assign。

    所以當 a、b、c 或 s 改變，組合邏輯就會開始產生新的結果。

    2.5 Propagation Delay（傳播延遲）是什麼？

    假設你把 a 從 7 改成 8。

    電路不會在真實物理時間的同一瞬間讓 d 完成變化。

    因為訊號必須通過加減法邏輯，再通過乘法器。

    所以存在：

    \[
T\_{\mathrm{total}}\approx T\_{\mathrm{add/sub}}+T\_{\mathrm{mult}} 
\]

    這是概念性估算，實際延遲由合成後的 Critical Path 決定。

    你可以把訊號想成經過兩個加工站的材料：第一個加工站完成加減法，第二個完成乘法。最終結果必須等資料傳到輸出後才能穩定。

    Non-Pipelined 最大的問題，就是整段算術路徑都在同一條組合邏輯路徑上。

    4.3 為什麼 Stage 1 連 c 也要存起來？

    這個問題非常關鍵。

    假設連續輸入兩筆資料：

    資料 a b c s 正確輸出
    A 7 3 5 1 50
    B 9 4 2 0 10

    資料 A 的正確計算是：

    \[
(7+3)\times5=50 
\]

    資料 B 的正確計算是：

    \[
(9-4)\times2=10 
\]

    假設 Stage 1 已經保存 A 的 a+b=10，而外部輸入開始切換成資料 B。

    如果 Stage 2 直接讀取外部輸入的 c，就可能錯誤地執行：

    \[
10\times2=20 
\]

    這樣等於把資料 A 的加法結果，和資料 B 的乘數混在一起。

    因此 Stage 1 必須同時保存 add_sub_q 和 c_q，確保第二級拿到的是同一筆資料。

    這稱為 Data Alignment（資料對齊）。

    4.4 你的 Pipeline Verilog 實際怎麼寫？

    我直接從你已封存的 Vivado Project Archive 中讀取 pipeline.v，確認你真正使用的程式是由三個 Module 組成：

    • hw2_pipe_stage1
    • hw2_pipe_stage2
    • hw2_pipe（Top Module）

    這也符合助教第 11 頁要求：Pipeline 的每一級分別寫成 Module，方便 Design Compiler 分析各級 Timing。

    第一級最重要的程式

    wire [15:0] add_sub_next;

assign add_sub_next = s ? (a + b) : (a - b);

always @(posedge clk or posedge reset) begin
    if (reset) begin
        add_sub_q <= 16'd0;
        c_q       <= 8'd0;
    end
    else begin
        add_sub_q <= add_sub_next;
        c_q       <= c;
    end
end

    這裡有四個重點。

    (1) posedge clk

    表示在 Clock 的 Rising Edge（上升沿）更新暫存器。

    (2) posedge reset

    表示 Reset 是 Active-High Asynchronous Reset（高有效非同步重設）。

    不需要等待下一個時脈上升沿，只要 reset 從 0 變成 1，就會執行重設動作，將暫存器清零。

    (3) <=

    這是 Non-Blocking Assignment（非阻塞指定），是同步暫存器設計的重要語法。

    (4) add_sub_q 和 c_q 同時更新

    這確保加減法結果與乘數屬於同一筆資料。

    第二級最重要的程式

    always @(posedge clk or posedge reset) begin
    if (reset)
        d <= 16'd0;
    else
        d <= add_sub_q * c_q;
end

    第二級在上升沿把乘法結果寫入 d。

    關鍵問題：同一個時脈上升沿，Stage 2 讀到的是 Stage 1 剛寫入的新值嗎？

    答案是：不是。

    因為使用 Non-Blocking Assignment，Stage 2 讀取的是上升沿之前，Stage 1 暫存器已經保存的舊值。

    這正是讓兩級 Pipeline 能夠在同一個時脈邊緣處理不同資料的原因。

    4.6 三個很容易混淆的概念：Delay、Latency、Throughput

    這是老師 HW2 第 8 題要求計算的重點。

    (1) Critical Path Delay（關鍵路徑延遲）

    假設每個 Stage 所需的最小時脈週期分別為：

    \[
T_1,\quad T_2 
\]

    因為兩級 Pipeline 會同時工作，所以整個設計能使用的時脈週期，必須滿足最慢的那一級。

    因此老師給的公式是：

    \[
\boxed{T=\max(T_1,T_2)} 
\]

    例如：

    \[
T_1=2\text{ ns},\quad T_2=5\text{ ns} 
\]

    那麼：

    \[
T=\max(2,5)=5\text{ ns} 
\]

    不是 7 ns。

    因為第一級做完以後，可以開始處理下一筆資料，不必等第二級完全閒下來。

    (2) Latency（延遲時間）

    Latency 是一筆資料從進入電路到產生輸出所需的時間。

    老師本題的比較表指定：

    \[
\boxed{T\_{\text{latency}}=T_1+T_2} 
\]

    以剛才的例子：

    \[
T\_{\text{latency}}=2+5=7\text{ ns} 
\]

    這是老師要求的各級運算延遲加總。

    但實際的同步 Pipeline 還要考慮 Clock Edge。

    在你的兩級程式中，資料會在第一個有效上升沿被 Stage 1 擷取，並在下一個上升沿由 Stage 2 產生輸出。所以不能把公式得到的 7 ns，直接當成任何時脈設定下實際等候輸出的時間。

    (3) Throughput（吞吐量）

    Throughput 衡量的是：

    電路在單位時間內，可以完成多少筆資料？

    老師給的公式：

    \[
\boxed{\text{Throughput}=\frac{1}{T}} 
\]

    假設時脈週期是 5 ns：

    \[
\text{Throughput}=\frac{1}{5\times10^{-9}} 
\]
    \[
=2\times10^8\text{ operations/s} 
\]

    也就是在 Pipeline 填滿以後，理想情況下每秒可以完成約兩億筆運算。

    三者最重要的差別

    名稱 問題 本作業的重點
    Critical Path Delay 最短可以使用多長的 Clock Period？ 由最慢的 Stage 決定
    Latency 單筆資料要多久才產生輸出？ 老師表格要求加總各 Stage 延遲
    Throughput 每秒能完成多少筆資料？ Pipeline 填滿後可每拍輸出一筆

    Pipeline 主要改善的是 Throughput，不保證縮短 Latency。

    4.10 Part 4 最重要的四個觀念

    1. Pipeline 是將較長的組合運算分成多個由暫存器隔開的 Stage。
    2. 使用 Non-Blocking Assignment <=，才能讓各 Stage 在同一時脈上升沿正確地使用前一階段保存的資料。
    3. Clock Period 由最慢 Stage 決定，而不是所有 Stage 延遲相加。
    4. 提高 Throughput 不等於降低 Latency。 Pipeline 用更多暫存器和面積，換取不同筆資料之間的重疊運算能力。

    這一部分也讓你看見，為什麼我們後面還要學 Clock Gating。

    因為 Pipeline 加入許多 Flip-Flops，即使某筆資料的 c=0、最後乘積必然為零，這些暫存器和內部運算邏輯仍可能持續切換、消耗 Dynamic Power。

    Part 5 就是研究如何避免這種不必要的切換，在維持 Pipeline 功能的同時降低功耗。

    5.2 Clock Gating 的基本原理

    Clock Gating 的核心方法是：

    當某些暫存器不需要更新時，暫時阻止 Clock 傳到這些暫存器。

    最簡單的概念可以用一個 AND Gate（反及閘以外的「及閘」）實現：

    \[
\boxed{gclk=clk\land en} 
\]

    其中：

    • clk：原本的時脈。
    • en：Enable（啟用訊號）。
    • gclk：Gated Clock（閘控後的時脈）。

    兩種情況

    當 en=1：

    \[
gclk=clk\land1=clk 
\]

    Clock 正常通過，暫存器可以更新。

    當 en=0：

    \[
gclk=clk\land0=0 
\]

    gclk 維持在 0，不再產生時脈上升沿。

    因此，使用 gclk 的正緣觸發暫存器就會保持原本的資料，不再因時脈觸發而更新。

    觀察 Clock Gating 對時脈的影響

    Enable = 1Enable = 0

    概念示意：切換 Enable，觀察原始 clk 與閘控後 gclk 的差異。

    這就是助教《Clock Gating 2026》第 4～7 頁介紹的 Non-Latch Clock Gating 基本原理。

    5.3 為什麼不能直接拿 AND Gate 當作最終實體電路？

    這裡要接上你剛才學會的 Setup Time。

    假設我們寫：

    assign gclk = clk & en;

    看起來很簡單，但有一個問題。

    如果 en 剛好在 clk 為 High 的期間改變，gclk 就可能產生不正常的時脈脈波。

    例如：

    • 原本 clk=1、en=0，所以 gclk=0。
    • 此時 en 突然從 0 變成 1。
    • 因為 clk 還是 1，gclk 會突然從 0 變成 1。
    • 接著 clk 很快又下降，造成 gclk 出現很窄的 High Pulse。

    這叫做 Glitch（毛刺）。

    而暫存器可能把這個不正常的脈波當作 Clock Edge，造成錯誤的資料擷取。

    更嚴重時，過窄的 Clock Pulse 可能違反暫存器的時脈脈寬等要求。

    wire en = (c != 8'd0);

    5.5 你的 Clock Gating 電路到底改了哪裡？

    這是整個 Part 5 最值得理解的地方。

    老師 HW2 第 9 題並不是要求「當 c=0，把整個電路停止」。

    老師的要求更精確：

    當 c=0 時，讓第二級乘法器的兩個輸入保持不變，同時讓這筆資料對應的輸出 d 為 0。

    這是兩件不同的事。

    (1) 讓乘法器輸入保持不變

    原本 Pipeline 的 Stage 1 有兩組暫存器：

    • add_sub_q：16 bits。
    • c_q：8 bits。

    合計：

    \[
16+8=24\text{ bits} 
\]

    Clock Gating 要控制的就是這 24 個暫存位元。

    當 c=0，不更新它們，Stage 2 乘法器看到的兩個輸入便保持原本數值。

    (2) 但輸出仍然要能變成 0

    想像前一筆資料 A：

    \[
(a+b)c=(7+3)\times5=50 
\]

    下一筆資料 B 的 c=0。

    這時候 B 的正確輸出是 0。

    如果你連輸出暫存器 d 的 Clock 都停止，會怎麼樣？

    d 就會一直保持 50，而不是更新成 0。

    這樣功能就錯了。

    所以你的 Clock Gating 設計除了閘控乘法器輸入暫存器之外，還用一個 nonzero_q 旗標，保存前一筆輸入的 c 是否為非零。

    Stage 2 的輸出暫存器仍由原本的 clk 控制：

    • 上一筆 c≠0：使用保存的運算元進行乘法。
    • 上一筆 c=0：輸出 0。

    用三筆資料看時脈順序

    假設：

    • A 的運算結果為 50。
    • B 的 c=0，結果應該為 0。
    • C 的運算結果為 18。
    Clock Rising Edge Stage 1 乘法輸入暫存器 nonzero_q 輸出 d
    第 1 拍（A） 保存 A 1 0（Reset 後初值）
    第 2 拍（B，c=0） 保持 A 0 50（A 的結果）
    第 3 拍（C） 保存 C 1 0（B 的結果）
    第 4 拍 保存下一筆 依下一筆而定 18（C 的結果）

    看第 2 拍：

    即使 B 的 c=0，Stage 1 保持 A 的運算元，Stage 2 仍然要完成前一筆 A 的輸出。

    等到第 3 拍，Stage 2 才根據 B 對應的旗標輸出 0。

    這就和 Part 4 的 Non-Blocking Assignment 與 Pipeline Data Alignment 連結起來了。

    Clock Gating 不只要省電，還必須維持每一筆資料原本的輸出拍次。

    5.7 Clock Gating 到底省了多少電？

    這是整份 Clock Gating 作業的主要評分重點。

    助教第 14 頁明確要求：

    • Pipeline 與 Clock Gating 使用相同的測試資料。
    • 比較 PrimeTime 的 Total Power。
    • Clock Gating 的 Total Power 必須小於一般 Pipeline。

    你這次的結果是：

    PrimeTime：VCD-based Total Power

    普通 Pipeline

    37.8 µW

    Clock Gating

    30.4 µW

    Clock Gating 的總功耗降幅

    19.58%

    我們手算一次：

    \[
\text{Power Reduction}= \frac{P\_{\text{pipe}}-P\_{\text{gating}}}{P\_{\text{pipe}}}\times100\\% 
\]
    \[
=\frac{37.8-30.4}{37.8}\times100\\% 
\]
    \[
\boxed{19.58\\%} 
\]

    也就是說，在這次相同 Clock、相同 200 筆測試資料下，Clock Gating 的 PrimeTime 平均總功耗估計下降約 19.58%。

    這不是直接在實體晶片上用儀器量到的功率，而是 PrimeTime 根據標準元件庫與 VCD 切換活動得到的分析結果。

    為什麼不是減少 50%？

    因為我們雖然安排了 50% 的測資為 c=0，但不是讓整個晶片在一半時間內完全停止。

    實際上：

    • 只有一部分 DFF 被 Clock Gating 控制。
    • 加減法組合邏輯仍可能切換。
    • 其他未閘控的暫存器仍然工作。
    • ICG 本身也需要額外的功耗。

    所以 50% 的 c=0 輸入，不代表功耗一定減少 50%。

    5.8 為什麼 Design Compiler 的 Power 反而變高？

    這是老師 HW2 第 4 頁特別提醒的問題。

    你實際的數據：

    指標 普通 Pipeline Clock Gating
    DC Total Cell Area (µm²) 169.413125 176.670725
    DC Critical Period (ns) 0.632429 0.646740
    DC Dynamic Power (µW) 187.7498 203.8873
    PrimeTime Total Power (µW) 37.8 30.4

    你會發現：

    Design Compiler 顯示 Clock Gating 的 Dynamic Power 反而比較高；PrimeTime 卻顯示它省電。

    這並不矛盾。

    Design Compiler 在未指定本次 200 筆 VCD 活動資料時，會依其活動估計方式進行功耗分析，並不一定反映 c=0 很常發生的真實測試情況。

    而 Clock Gating 又新增了 ICG 及相關控制邏輯，所以在 DC 的估計下，功耗可能增加。

    PrimeTime 則使用你的 Testbench 所產生的 VCD，能觀察到部分 Clock 和暫存器確實不再切換。

    因此，你應該使用相同測試條件下的 PrimeTime 結果，來評估這次 Clock Gating 的節能效果。

    Clock Gating 的代價

    這項技術也不是只有好處。

    相較於普通 Pipeline：

    • Cell Area 增加約 4.28%。
    • DC Critical Period 增加約 2.26%。
    • PrimeTime Total Power 減少約 19.58%。

    這就是 Power、Performance、Area 之間的 Trade-off。

    5.9 Part 5 核心總結

    你現在應該掌握以下觀念：

    1. Clock Gating 主要用來減少不必要的切換活動，降低 Dynamic Power。
    2. 簡單用 AND Gate 控制 Clock 可能產生 Glitch，因此實體電路會使用較安全的 Latch-Based ICG。
    3. 這次 HW2 必須使用助教指定的 Method 2：Non-Latch RTL → Design Compiler replace_clock_gates → Latch-Based ICG。
    4. 停止乘法器輸入暫存器更新，不代表可以停止所有輸出暫存器；每一筆資料的功能與 Pipeline 拍次仍要正確。
    5. 你的實際設計使用 1 個 ICG、控制 24/41 個 DFF，PrimeTime Total Power 降低約 19.58%。

    一個觀念確認

    為什麼當 c=0 時，我們不乾脆直接把整個 Pipeline 的 Clock 都關掉？

    答案： 因為前一筆資料仍可能需要在這一拍輸出，而且 c=0 這筆資料本身也必須在對應的輸出拍次產生 0。如果連輸出暫存器都停止，就可能保留舊結果，讓功能錯誤。

    這是你這份 Clock Gating 設計最重要的地方。
